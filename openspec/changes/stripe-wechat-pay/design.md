## Context

当前 Stripe 只创建银行卡 Checkout。Stripe 微信支付需要使用 `wechat_pay` 及 `payment_method_options.wechat_pay.client=web`。预发 Stripe Sandbox 已只读核对默认支付方式配置，微信可用且开启。

## Goals / Non-Goals

给人民币 Stripe 商户启用独立的扫码方式，保留现有异步入账与退款语义。Stripe 支付宝、其他币种及钱包变更不纳入本次。

## Decisions

- 使用可选的微信最低金额字段表示方法启用；对历史设置解析时不填默认值，以保留凭据密文的认证数据。Stripe 账号身份、银行卡请求参数和历史订单版本绑定保持兼容。
- 保存后校验 Stripe 当前账户、币种及默认支付方式配置。报价和建单复用支付能力与报价重验，微信金额使用整数最小单位，最高金额仍受价格政策及平台限制。
- Checkout 只允许已报价的支付方式。微信 Session 和 PaymentIntent 均保存方式 metadata，成功规范化校验 Stripe 对象的唯一可用方法；最终入账还校验订单方式。回调先持久化和 ACK，再用现有支付观察状态机处理，查询恢复经相同入口。
- 无状态变更发生在未付款、付款方式不符或回调重放上。复用订单锁、额度、唯一支付事实、唯一入账及已绑定的渠道退款幂等键。待确认或失败沿用现有查询与关单，最终退款以渠道事实为准。
- 清空微信最低额并激活或回滚至旧版本可停止新微信订单，历史订单沿原版本处理。

## Risks / Trade-offs

- Stripe Sandbox 只证明沙箱行为；正式账号配置和小额付款验证按发布窗口执行。
- 原发布 hotfix 尚未回并 develop。先将生产修复和 develop 的支付模块边界合并，再从经验证的共同基线实现。
