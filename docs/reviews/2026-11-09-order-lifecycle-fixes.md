# 订单生命周期 review 修复（2026-11-09）

修复基于 `develop@74d6f56`，对应 `406e2e3` 上的五项 review 发现，集中在一个 PR。无数据库迁移；不包含生产数据修复或部署。

| 问题 | 修复后的行为 | 主要回归证据 |
| --- | --- | --- |
| ORD-001：外部任务进入平台人工履约 | 在订单锁内检查规格绑定及持久任务；即使解除绑定，也禁止人工接单、拒单、交付、进度和无法履约操作。取消意图阻止人工接单，保留系统迟到成功的处理。 | `server/src/__tests__/order-lifecycle-review-regressions.test.ts`：远端执行期间逐项拒绝人工操作，随后正常交付扣款；取消待核对订单只退款一次。管理端组件和投影测试验证按钮隐藏及任务输入不泄露。 |
| ORD-002：交付后继续履约再退款回补名额 | 是否已消耗名额以交付记录为准；已交付订单恢复 processing 后退款，不回补服务容量。 | 同上：买家接受补救、管理员继续履约两条路径均验证容量不变、全额退款和结算作废。 |
| ORD-003：逾期回应覆盖原期限 | 商家提案和买家回应均在订单锁内校验期限；逾期返回 409，原定时处理仍可执行。 | 同上：逾期商家提案后自动退款；逾期买家接受及拒绝均不能覆盖超时处理。 |
| ORD-004：通用购买参数丢失 | 预览和下单统一传递有界 `extensionInput`；供应商参数进入幂等指纹，键顺序不影响重放，字段缺席、空字符串及不同原始类型保持区分。保留 Xboard 顶层字段并在适配器内校验嵌套账号参数。 | 同上：HTTP 预览→prepare→任务快照完整传递，改目标及空字符串/缺席冲突返回 409。`fulfillmentInput.test.ts` 验证边界和规范化；`paid-reset-checkout.test.ts` 验证嵌套无效账号参数返回 400，积分及任务数量不变；`src/api/orders.test.ts` 验证前端封套。 |
| ORD-005：历史 NULL 期限争议进入自动补救 | NULL 回应期限的历史争议保留管理员裁决，商家无法提交补救，也不显示该操作。 | 生命周期回归验证商家提案被拒、定时器跳过，以及管理员仍可退款。 |
