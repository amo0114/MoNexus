# develop 质量问题修复记录

基线：`origin/develop` / `60ea3c6189a1b0b10a36f732868a6e370aa0537f`。本轮对应复评中选定的 10 项；没有数据库迁移，也没有连接生产库。

## 已实现

| 范围 | 结果 |
|---|---|
| 备份 | 本地脚本和 Actions 共享 URL 过滤函数，只去掉非 libpq 的 Prisma 连接池/schema 参数，保留 TLS、证书及其他参数的原始编码。URL 模式新增 Python 3 运行依赖。 |
| 买家订单 | 新增 `/api/orders/page`，查询、状态计数、排序与分页在服务端执行；旧数组接口保留。商品/规格/商家支持文本包含查询，完整订单号精确匹配；通知深链直接打开订单详情。 |
| 路由体积 | 用户、商家、管理员及低频页面改为懒加载；保留商城和登录入口。主 JS gzip 从基线约 522.59 kB 降到 157.13 kB，约减少 70%。这是入口文件指标，不等同于页面加载时间。 |
| 商城候选 | 两个位置接口后只追加一次最多 12 个 ID 的卡片投影请求，复用当前可见性审核；不再逐件请求商品详情。候选超时后降级到普通商品。 |
| 评价 | 加载期间禁用加载更多，避免连续点击推进到下一页并丢弃尚未返回的数据。 |
| 无障碍 | 首页商品卡片使用真实链接；购买表单和密码输入关联 label/id。 |
| 登录限流 | enforce 模式使用现有 Redis/HMAC bucket，登录、MFA 等既有路由共享 IP 额度，Redis 不可用时沿用安全限流组件的拒绝策略。开发 off 模式保留本地限流。 |
| 密文保留 | 过期终态事件在短事务中按 Event → RechargeOrder 加锁，锁内重查案件并清除；对账案件写入使用相同订单锁。也识别仅关联订单、未关联支付尝试的争议。 |
| 真实依赖 CI | 新增 Redis 与隔离 S3 job 并接入 CI OK；缓存测试确认真实 Redis 中存在预热值。MinIO 固定源码 commit 构建，避免依赖不可拉取的旧公共镜像。 |
| 视频运营 | 持久队列数量、最老排队年龄、过期租约与处理耗时指标；审核历史服务端分页；提供 Prometheus 示例规则。 |

## 验证

- Node 22 前后端生产构建通过，后端构建产物导入检查通过。
- 选定后端套件累计 81 项通过：订单、公开商品投影、登录共享限流、支付入账、密文保留、视频处理/审核/队列指标、真实 Redis 缓存撤权。普通视频套件的一个可选 Redis 用例未启用；独立缓存撤权用例已使用真实 Redis 执行。
- 选定前端 35 项通过，覆盖商城候选与分页请求协调、评价并发加载、审核分页、商品卡片。
- 浏览器回归 7 项通过：移动端 3、注册/登录/会话 1、结算确认/改价/表单变更 3。均使用隔离服务或 API 测试桩。
- PostgreSQL 16 / Redis 7 / MinIO 真实依赖验证；固定 MinIO 源码构建及同版本 S3 用例也通过，S3 检查包含匿名拒绝、Range 206/416、MIME/no-store、篡改和过期签名、付费文件下载。
- 备份 URL 3 项测试、架构/OpenAPI 引用、部署脚本契约、工作流 actionlint 结构检查及 diff whitespace 检查通过。

## 已知边界与后续

- 未运行整个项目全量测试、未推送触发远端 Actions、未部署。Prometheus 规则需要运维加载。
- `check:bundle-budget` 当前仍失败：它统计全部构建产物，约 780 KiB gzip，高于既有 150 KiB 阈值。本轮保留阈值；管理员页面约 528 kB raw，后续可继续按管理面板拆分，并分别建立入口和低频路由预算。
- 订单号搜索明确使用完整号码；通知深链打开详情，不计算目标卡片在当前筛选列表中的页码。
- MinIO 官方当前说明社区版采用源码分发；本轮实测 Docker Hub/Quay 拉取失败、旧下载地址返回 410，因此 CI 使用固定源码 `01ce918d8279a20e4706b96a64396146894adee4`，作为一次性测试夹具。没有改动生产对象存储部署配置。[官方来源（2026-10-24 核对）](https://github.com/minio/minio#source-only-distribution)
- actionlint 开启 shellcheck 时，备份 workflow 原有脚本仍有 SC2086/SC2129 提示；本轮新增 workflow 逻辑没有对应提示。
