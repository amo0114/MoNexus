## 1. 目的与边界

为 PR3（创建字段名称建议）和 PR4（弱匹配准入调整）提供事实依据。本轮只做以下几件事：

- 只读：脚本只执行 SELECT，不更新商品，不做自动清洗，不调整推荐规则。
- 只看目录元数据：商品名、分类、模板与公开属性、商家名、外部导入记录。不读库存条目内容、固定交付内容、订单或买家资料，也不调用 Xboard。
- “待确认”项只是供人工核实的线索，不代表应合并或改写。例如 Steam 与 Steam Wallet 不会被自动视为同一服务。
- 测试库或本地演示数据的统计不能当作线上结论。

## 2. 数据入口（运行前确认）

| 选项 | 要求 |
| --- | --- |
| 首选：已授权的数据库快照 | 记录快照时间、来源环境和授权人；在隔离环境恢复后运行 |
| 备选：已授权的生产只读账号 | 账号必须只有 SELECT 权限；不得使用应用写账号 |

本次使用经项目负责人授权的生产临时只读账号，通过 SSH 隧道访问；脚本在本地隔离 worktree 运行。账号只授予审计所需的 5 张表的指定列 SELECT 权限，不使用应用写账号。连接串与凭据不写入本文件、日志或提交。

## 3. 运行方式

```bash
# 使用 Node 22 / npm 10，DATABASE_URL 指向快照或只读账号；--silent 避免 npm 提示混入结果
REDIS_ENABLED=false npm --silent --prefix server run recommendation:audit -- --format=json --samples=50 > audit.json
REDIS_ENABLED=false npm --silent --prefix server run recommendation:audit -- --format=md  --samples=20 > audit.md
```

- JSON 是事实来源；总数基于全部范围商品，名称表和待确认列表受 `--samples` 上限约束，不能把样本列表当作完整清单。Markdown 是第 4 节可以直接粘贴的正文。本次使用 `--samples=200`，2 件商品未触及样本上限。
- 输出里含商品名和商家名，原始 JSON 不提交到仓库；本报告只放汇总和必要样本。
- 推荐模拟会对每件范围内商品执行 2 次候选查询。商品较多时，尽量在快照上运行，避免占用生产库。

### 指标口径

| 章节 | 口径 |
| --- | --- |
| 范围 | `status=active`、未归档、经营者有效（平台自营或商家 active）；包含 public 和 members_only；另行标注是否有启用套餐 |
| 完整度 | 按分类 × 模板（`key@version`，无策略即 legacy/unknown）分组；主匹配字段用推荐 SQL 的同一归一化规则判断已填/缺失；manual_service、appointment 没有主键，记为“—” |
| 名称分布 | serviceName、contentCategory 分别统计；按规则归一化值分组并列出原始写法。疑似同义使用更宽松的键（NFKC、大小写、空白、标点）和包含关系，仅作线索 |
| 旧模板占比 | templateKey/version 为空或不在策略表中的商品占比，按分类拆分 |
| 推荐位 | 每件商品作为基准，以登录用户视角调用与接口相同的候选 SQL，统计前 6 个位置，**在可售过滤之前**（实际接口对完整的最多 128 个候选补全、过滤后再取六件，后续候选可能补位，最终商品与位置需单独核验）；“同店弱匹配占位”指前 6 中有同店 tier<3、而跨店 tier3 落在第 6 位之后 |
| 来源 | 外部导入以 `ExternalCatalogLink` 为准；另列“有 Faka 套餐但无导入记录”；导入名称中的周期/套餐/版本词只做标记。AI 创建来源**无法区分**：`AiGeneration` 只记录调用，不记录内容是否被采用 |

- 运行时间：2026-10-14 21:50:51–21:50:58（Asia/Shanghai，UTC 13:50:51–13:50:58）；JSON 生成时间为 `2026-10-14T13:50:55.269Z`。直接查询生产库，非数据库快照。
- 审计代码：`chore/recommendation-data-audit@2b4f8c3`，执行一次 JSON 审计。
- 线上版本：实际核对前后端镜像均为 `sha-7dc79aa`。以下推荐位指标是使用新推荐规则对现有生产目录的模拟，不是线上推荐功能已经部署的证据，也不是实际曝光或点击数据。
- 范围商品数 / 有启用套餐：2 / 2；均属于网络节点（`network-node`）。范围包含 public 与 members_only，不含草稿、下架、归档或经营者无效的商品。
- 范围核验：本次确认应用实际使用的生产库（`monexus` / `public`，与 monexus-db-prod 一致）共有 5 件商品：active 且未归档 2 件、inactive 未归档 2 件、inactive 已归档 1 件；2 件 active 商品分属 1 个 active 商家和平台自营，没有 active 商品因归档或商家停用被排除。2026-09-29 提交（`1ec52f9`，#228）中提到的 830 件 active 商品来自本机库实测，不能与本次生产统计直接比较。

## 5. 结论与后续输入

当前可确认的目录问题是范围商品全部使用旧版或未知模板；无法评估模板主匹配字段的完整度与同义名称问题。商品数量与模板覆盖不足，无法评价规模化推荐质量、转化效果或同店优先的实际影响。

- PR3：暂不根据本次数据建立标准名称或别名表；先由经营者确认现有商品的适用模板及字段含义，再制定创建字段建议。本轮不修改历史商品，也不强行套用某一模板。
- PR4：暂不调整弱匹配准入。当前两个候选都是 tier1，直接排除旧模板弱匹配会使两件商品都没有候选；缺少改进质量的证据。
- PR5：可以继续设计事件契约，但本报告没有曝光、点击或兑换归因数据，不能作为效果统计结果。
- 复审条件：目录出现已知模板商品、多种属性写法或足够的同店 / 跨店强匹配样本后，按相同口径重新运行。无需为了本轮小样本增加算法或数据库结构。
