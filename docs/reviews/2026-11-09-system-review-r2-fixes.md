## 人工核对边界

人工证据由已通过 MFA 的管理员核实，服务端只保存和审计，不能自行验证供应商工单真实性。操作者必须确认对应操作键已经撤销且不会延迟执行，不能把 404、超时、租约到期或订单年龄作为证明。租约结束只是允许开始人工确认的必要条件。

旧 webhook 停止重试时保留在途租约。该任务的认领锁序与订单相反，人工确认用 `FOR UPDATE SKIP LOCKED`，遇到正在认领直接拒绝。Xboard 不开放人工备注退款，继续使用既有 revoke tombstone 核验。

## 迁移失败处理

生产和自动化使用 `npm --prefix server run db:migrate:deploy`，迁移连接启动参数设置 lock_timeout=5s；不依赖 Prisma 不读取的 libpq PGOPTIONS。5s 限制的是等待锁，不是整次迁移时长，也不保证一个已经拿到的锁只持有 5s。新增索引必须单独并发创建，避免强锁覆盖索引构建。

遇到锁超时应中止发布并检查长事务。Prisma 可能将迁移标记为失败；先检查数据库实际 DDL 状态，再按迁移恢复流程处理，不能盲目 `resolve --applied`。已执行的历史文件保持不变。
