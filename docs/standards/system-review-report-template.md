# 系统评审报告模板

> 配套 [`system-review-standard.md`](./system-review-standard.md) 使用。
> 复制本文件到 `docs/reviews/<YYYY-MM-DD>-<主题>/`，按 §0 起逐节填写。
> **删除所有斜体提示文字后再交付。**

---

## 0. 基线与范围

| 项 | 值 |
| --- | --- |
| 评审基线 commit | *完整 SHA + 提交标题 + 时间* |
| 分支 | *...* |
| 与远端的差集 | *`git rev-list --left-right --count HEAD...origin/develop`* |
| 工作区偏差 | *未提交文件清单及其对结论的影响；无偏差则写"无"* |
| 运行时 | *Node / npm / PostgreSQL / 其他* |
| 可弃数据库 | *库名与迁移版本* |
| 依赖锁定 | *lockfile 是否与基线一致* |

### 0.1 项目类型与维度权重

*声明项目类型（电商资金 / 安全网关 / Agent / 前端体验 / 基础设施），并说明为何某些维度权重更高。参考标准 §1.1。*

### 0.2 本轮明确不覆盖

*必须比"已覆盖"写得更保守。列出：未审的模块、未做的动态验证、无法访问的环境。*

### 0.3 环境限制声明

*哪些结论因环境限制只能停在静态推演。凡受限项，证据状态一律 NOT_VERIFIED。*

## 1. 系统模型

*只描述事实，不做质量判断。*

### 1.1 业务域与角色

*角色、数据锚点、入口前缀、核心职责。*

### 1.2 模块依赖

*静态 import 边；标出双向依赖。*

### 1.3 状态机

*每个有状态字段：状态全集、允许转移、唯一权威实现位置、谁能写。*

### 1.4 数据流与事务边界

*关键链路图；标出事务起止、锁顺序、远程调用位置。*

### 1.5 权限矩阵

*入口 × 角色 × 守卫中间件。*

## 2. 业务不变量

*每条按标准 §2.2 格式：*

```
INV-xx  <不变量陈述>
├── 业务含义
├── 强制机制：DB 约束 / 应用层 CAS / 事务隔离 / 唯一索引 / 仅靠约定(=GAP)
├── 覆盖范围
├── 状态：VERIFIED / PARTIAL / GAP / NOT_VERIFIED
└── 证据：代码位置 + 测试或运行证据
```

## 7. 发布结论

**结论：允许发布 / 有条件发布 / 禁止发布 / 证据不足，无法判定**（四选一，删除其余）

### 7.1 判定依据

*按标准 §8 的条件逐条对照。*

### 7.2 阻断项

*列 P0 与无法缓解的 P1。无则写"无"。*

### 7.3 若是"有条件发布"，条件是什么

*功能开关、灰度范围、限额、监控项、回滚方案。*

### 7.4 证据缺口

*哪些关键结论停在 NOT_VERIFIED，为什么不能在发布前补齐。*
