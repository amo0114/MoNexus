## 2026-10-23 的上线决定

用户已了解优选 SaaS 分段响应的浏览器缓存问题，明确要求先开启生产视频播放，将“独立媒体出口、签名配置调整及缓存/授权复测”记录为后续工作。本次仅调整生产运行开关，沿用已部署版本 `8047504439cff444166af6312184cde5c27af616`，不更换整站加速线路，不放开私有桶，也不跳过商品可见性和公开审核门禁。

已通过[正式生产部署](https://github.com/amo0114/MoNexus/actions/runs/39820208962)重建容器，部署成功；实际运行开关已核对为：

```dotenv
PRODUCT_VIDEO_UPLOAD_ENABLED=true
PRODUCT_VIDEO_PLAYBACK_ENABLED=true
```

该决定接受当前缓存降级，不代表缓存验收已通过。源站视频完整响应与分段响应均返回 `private, no-store`，但实测优选 SaaS 将分段响应改为 `private, max-age=14400`。浏览器可能复用已获取的片段；退出登录、撤销批准和短期签名失效不能使这些本地缓存立即消失。重新请求源站的过期签名仍返回 403，不能将浏览器缓存期限理解为服务器签名有效期延长。本次 CDN 返回 BYPASS，未观察到共享 CDN 缓存泄露。

主站使用第三方优选 SaaS 加速，用户不管理该加速链。在自身区域配置规则后，诊断请求未出现新增的响应头，未能确认这些规则控制了实际媒体流量；不能把“规则已创建”当作修复完成。开放后的某次小样分段请求返回 `no-store`，但立即复查 38 MiB 样片仍返回 `private, max-age=14400`，不能因单个响应正常就关闭问题。

## 后续：独立媒体出口与签名配置

状态：待实施；本次先开放播放，不把此项标为完成。

1. 主站保留现有优选 SaaS，为商品视频及海报建立自己可控的 HTTPS 媒体域名和代理出口，避开不可控的缓存改写。私有桶保持匿名不可读，限制代理暴露范围，不开放 MinIO 管理入口。
2. 在签发时使用真实的媒体公网域名生成签名。S3 SigV4 包含 Host，**禁止生成旧域名签名后直接替换 URL 域名**。现有适配器的视频与付费附件共用公网签名 client，实施时明确是否新增视频专用配置，避免顺带改变付费交付行为。
3. 配置证书、Host/原路径/查询串透传、Range、必要的跨域策略与日志脱敏；不记录完整签名 URL。
4. 完成下面的实际生产复测后，才将缓存问题关闭：
   - 完整视频 200、分段 206、海报均保留 `private, no-store`；不从共享缓存命中。
   - Range 字节与 Content-Range 正确，非法 Range 返回 416。
   - 匿名、篡改签名、过期链接的新请求均拒绝；有效签名可播放。
   - 播放凭证接口继续执行商品生命周期、分类、用户身份及当前内容版本批准门禁；视频替换/移除使旧批准失效。
   - 如涉及共用的交付配置，回归付费文件仍为 attachment/octet-stream。
   - 原生播放器的声音、拖动、暂停、重播和资源释放正常。
