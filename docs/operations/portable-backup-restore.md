# 可移植应用备份与恢复

本功能用于把一个 MoNexus 实例的数据迁移到另一台已部署 MoNexus 的机器。它完全通过
PostgreSQL 与 S3 兼容对象存储工作；不依赖 1Panel、Docker volume、宿主机路径或云厂商
快照。

## 备份包包含与不包含的内容

一个 `*.monexus-backup` 包包含：

- PostgreSQL 业务数据库的逻辑转储；
- 所有 MoNexus 内容寻址上传图片（不会打包共享 bucket 内的无关对象）；
- （格式 v2 起）私有交付桶（`DELIVERY_STORAGE_BUCKET`）里的全部受控交付文件
  （P5；`tmp/` 临时对象不入包），恢复时写回目标实例的私有桶；
- 文件清单、大小、SHA-256、创建时间和包格式版本。

> 版本兼容：v2 之前的服务器导入 v2 包会在格式校验处直接失败（而不是静默丢弃
> 交付文件）；新服务器仍可导入旧的 v1 包（其中本就没有交付文件）。

它**不包含** `.env`、数据库/对象存储密码、JWT 密钥、SMTP/Sentry 配置、反向代理配置、
Docker 数据卷或任何宿主机设置。目标机器必须自行配置这些运行环境变量。

包由管理员输入的口令以 `scrypt + AES-256-GCM` 加密。口令不会写入数据库、任务状态、
日志或审计详情。

## 创建备份（源实例）

1. 使用管理员账号登录旧实例。
2. 进入“管理后台 → 数据备份与恢复”。
3. 输入一个至少 12 字符、独立保存的备份口令，点击“创建备份”。
4. 等待状态显示“已完成”，下载 `.monexus-backup` 文件。
5. 将备份文件和口令分别安全保存。丢失任一项都无法恢复。

创建期间服务继续运行；PostgreSQL 转储本身是一致性快照。对象采用内容寻址 key，适合
这类追加式上传存储。

## 导入到新实例（目标实例）

### 1. 部署目标实例

部署与通常生产环境相同的 MoNexus（推荐与源实例相同或更高的应用版本），并配置自己的：

- `DATABASE_URL` / PostgreSQL；
- `STORAGE_*` / S3 或 MinIO；
- `JWT_SECRET`、`METRICS_TOKEN`、邮件与站点域名等环境变量。

目标数据库必须没有业务数据。**不要**执行演示 seed，也不要向目标实例创建商品、订单、
商家或上传图片；若使用共享对象存储 bucket，备份中将要恢复的同名 MoNexus 图片也必须
不存在。共享 bucket 的其他对象不受此功能影响。

目标机器需要有足够临时磁盘空间；建议至少预留源数据（数据库加对象）未压缩体积的 4 倍。

### 2. 创建引导管理员（纯前端）

在目标实例的 `.env` 额外设置一个新的高熵值：

```env
PORTABLE_RESTORE_BOOTSTRAP_TOKEN=自行生成的长随机字符串
```

重新部署/重启目标实例后，访问：

```text
https://你的新域名/restore-setup
```

输入该令牌、一个管理员邮箱和至少 12 字符的管理员密码。此入口只有在 `User` 表完全为空
时才可用，成功一次后自动关闭。随后用这个引导管理员登录。

### 3. 导入

1. 登录后进入“管理后台 → 数据备份与恢复”。
2. 选择 `.monexus-backup` 文件，输入创建时的口令。
3. 阅读确认提示并点击“导入备份”。
4. 导入先恢复并校验对象，再恢复数据库；完成后页面会退出登录。
5. 使用**引导管理员**重新登录。它会被保留；备份中的其他管理员也会被恢复。

所有旧 refresh token、密码重置 token 和邮箱验证 token 会被删除，所有用户需要重新登录。
如果新站的域名、CDN 或对象存储 URL 与旧站不同，已恢复的 MoNexus 商品图片会自动换成
新地址；外链图片不会被改写。

成功导入后，从目标 `.env` 删除 `PORTABLE_RESTORE_BOOTSTRAP_TOKEN` 并重新部署/重启。

## 上传限制与反向代理

默认单包上限是 2 GiB，可通过 `PORTABLE_BACKUP_MAX_BYTES` 调整。仓库中的 Web Nginx
只对下列精确路径放宽上传大小和超时：

```text
POST /api/admin/portable-backups/import
```

若前面还有其他反向代理、CDN 或负载均衡，需要对同一路径设置至少相同的请求体上限和
15 分钟以上的读写超时；下载路径也应允许至少 15 分钟的响应传输。不要把全站
`client_max_body_size` 提升到备份大小。

## 失败处理与边界

- 错误口令、篡改包、校验失败、未知格式：不会写入数据库；重新选择正确文件即可。
- 对象恢复失败：数据库尚未恢复；系统会尝试删除本次已写入的对象。确认对象存储为空后，
  修复配置并重试；若清理也失败，请重建目标对象存储/实例后再试。
- PostgreSQL 转储阶段失败会以单事务回滚，系统也会尝试删除本次已写对象；确认目标仍为空
  后可修复原因并重试。若数据库已提交后才在兼容迁移或后处理阶段失败，不要尝试合并或
  再次导入，清空/重建目标实例后重新导入。
- 非空业务数据库或目标中已存在的同名 MoNexus 图片会被明确拒绝，避免覆盖或合并已有
  业务数据；共享 bucket 的无关对象不会阻止恢复。
- 此功能用于迁移与人为创建的完整备份，不替代云硬盘快照或异机灾备。
