# 运行时配置与精简部署

本说明对应 `feat/admin-runtime-settings`。它扩展早期
`registration-gate-and-mail-operations.md` 中仅提供邮件状态/测试的范围。
旧环境文件继续兼容；升级不会自动创建或激活新的 SMTP 配置。

## 配置归属

| 归属 | 内容 | 修改何时生效 |
|---|---|---|
| 部署环境 | 数据库、Redis、域名/代理拓扑、安全根密钥、监控和备份 | 重启/重新部署，密钥需受控轮换 |
| 通用后台配置 | 奖励、会员、订单规则；本期新增站内通知启用与保留天数 | 后续请求/任务；订单快照规则保持不变 |
| 业务邮件后台 | SMTP 主机、端口、TLS、发件地址/名称、加密账号密码 | 测试并激活后的后续发送 |
| AI 后台 | 开关、地址、协议、模型、加密 API Key | 后续任务 |
| 存储后台 | 已有配置草稿、测试、激活、回滚 | 新上传；各实例的版本检查间隔为 2 秒 |
| 短链后台 | API/公开 origin、分组、加密登录凭据 | 激活后的新建请求；已有链接保留 |
| 履约后台 | FakaBridge/Xboard 目标、参数与加密凭据 | 新任务；历史任务继续使用绑定版本 |
| 支付后台 | 五渠道商户、加密凭据及新收款启停 | 新报价/订单；历史交易继续使用原账号与版本 |

首次部署可复制 `.env.minimal.example` 为 `.env`，替换占位符；完整可选项参考
`.env.example`。使用宿主反代时按现有 VPS runbook 配置 loopback overlay，
并调整 `DEPLOY_TOPOLOGY` 和 `TRUST_PROXY`。首次生产环境如果仍钉在 Turnstile，
保留既有 provider 和凭据，不能因为复制模板而擅自切到 ALTCHA。

生产监控和备份门禁仍然保留，因此精简模板也保留告警 SMTP 和恢复演练参数。
`npm run prod:env` 不连接数据库，也不能证明后台业务服务已就绪。

## 业务 SMTP

1. 升级时先执行数据库迁移，再部署应用。新表 `MailRuntimeConfig` 初始为空。
2. 如需在后台保存认证凭据，在部署密钥中配置独立的
   `MAIL_CREDENTIALS_ENC_KEY`（64 位十六进制，32 字节），所有 API 实例一致。
   未配置时仍可使用原环境 SMTP；后台拒绝保存认证凭据。
3. 管理员完成 MFA 并拥有 `settings.manage` 后，进入系统配置 → 高级运维 →
   业务邮件设置，填写参数并保存草稿。账号和密码只用于提交，查询接口不返回它们。
4. 向自己控制的邮箱发送固定内容的草稿测试邮件，确认收到后激活。
   SMTP 接受投递表示测试通过，不等于最终进收件箱或邮件域名配置正确。
5. 激活后数据库是业务邮件的权威来源，各实例的下一次发送读取新快照。
   已开始的发送继续使用原快照。草稿编辑不改变生效配置。
6. 可回滚到上一版；首次激活的上一版是**当前部署环境配置**，可能是 console
   模式。回滚不清除草稿，且会使草稿测试失效，需要重新测试后再次激活。

保存、测试、激活、回滚均带 `expectedVersion`；并发编辑冲突返回 409。
修改主机或端口时必须重新提供凭据或明确选择免认证 relay，防止把旧密码发往新目标。
测试使用现有 SMTP 发送 deadline，不自动重试；与原投递测试共用每管理员
10 分钟 3 次的进程内限流。多实例部署仍需另行配置共享 limiter store。

用户名与密码整体使用 AES-256-GCM 加密，数据库备份包含密文；根密钥必须单独保管。
密文绑定 SMTP 参数，修改数据库中的目标地址会导致解密失败。认证连接必须使用
TLS：465 通常使用直接 TLS，587 使用强制 STARTTLS；免认证 relay 可使用内部明文连接。
审计只记录版本、动作、结果和脱敏收件地址。解密失败时邮件服务报不可用，
不会静默改用环境中的旧账号。管理配置接口仍可用于替换损坏凭据。

监控 Alertmanager **继续读取宿主 `.env` 的 `SMTP_*` 和 `ALERT_EMAIL_TO`**。
后台改业务 SMTP 不会改写主机文件，也不会改变监控告警服务。

## 邮件加密根密钥轮换

将旧根密钥保留为 `MAIL_CREDENTIALS_ENC_KEY_PREVIOUS`，设置独立的新
`MAIL_CREDENTIALS_ENC_KEY`，向所有实例部署两把密钥。保存草稿时会把保留的凭据
重新加密到新密钥；重新测试并激活后，活动版本使用新密钥。

不要立即移除 previous key：上一版回滚配置或其他保留快照可能仍依赖旧密钥。
确认不再需要旧快照并完成恢复演练后才能移除。根密钥与数据库备份一起被恢复时，
需恢复对应的密钥版本；只有数据库备份无法恢复凭据。

## 通知与配置来源

`notificationEnabled` 和 `notificationExpiryDays` 缺少数据库记录时，沿用
`NOTIFICATION_ENABLED` 和 `NOTIFICATION_EXPIRY_DAYS`；后台首次保存对应键后，
该键改由数据库控制。禁用不删除历史通知，不影响验证码、密码重置等业务邮件。
修改保留天数只影响新通知的到期时间。

REST、写入和新 SSE 连接均检查动态开关。已建立的 SSE 不被强制断开；关闭后不再
创建新通知。浏览器可见时约每 30 秒重新读取公开能力，回到前台时也刷新。
`NOTIFICATION_REALTIME_ENABLED` 仍是需要重启的监听器配置，可以先开启监听器，
再从后台启用站内通知。连接上限、心跳等运维参数继续留在环境中。

`NOTIFICATION_EMAIL_ENABLED` 是旧兼容字段，当前没有实现对应的邮件通知通道，
本期不把它做成误导性的后台开关。

AI 数据库记录存在后，保存的开关和 API Key 覆盖 env bootstrap。
旧环境里开启 AI 但缺少 `OPENAI_API_KEY` 不再阻止整站启动；没有数据库凭据时
AI 本身保持不可用。`AI_CREDENTIALS_ENC_KEY` 仍属于部署安全根。

存储继续遵守现有 `STORAGE_CONFIG_SOURCE`：`database` 使用后台覆盖层，`env`
固定使用环境底座。生产 `STORAGE_*` 和私有交付桶仍是必需的恢复/基础配置，
本期不移除它们，也不改变历史文件的 provider 绑定。

## 第二阶段：短链与外部履约

新增迁移依次为 `20261113130000_integration_runtime_settings`、
`20261113140000_faka_runtime_binding`、`20261113150000_payment_runtime_binding`、
`20261113150100_payment_revision_account_index`（独立并发索引迁移，不放入事务）。
先迁移再部署前后端。数据库中的不可变版本必须随完整业务备份保留，不能手工删除。

所有 API 实例部署独立的 `INTEGRATION_CREDENTIALS_ENC_KEY`（64 位十六进制）。
凭据组使用 AES-256-GCM 加密，AAD 绑定服务、草稿/版本身份和公开参数。根密钥不入库。
未部署根密钥仍可使用原环境配置，但不能在后台保存、激活或轮换凭据。
保存、测试、激活、启停、回滚和根密钥重包均需要 MFA、`settings.manage`、
`expectedVersion`；并发修改返回 409。查询、审计都不返回明文凭据或密文。

系统配置 → 高级运维新增：

- **商品分享短链**：填写两个 HTTPS origin、分组、账号密码，保存后探测登录并激活。
  探测不创建短链，不能证明分组或创建权限。新建租约固定配置版本，进行中的请求
  允许用旧版本完成；停用后已有 ready 链接仍按当前商品访问权限复用。
  首次回滚目标是当前部署环境底座，后续回滚使用保留版本。
- **FakaBridge / Xboard 履约**：配置同站点、固定路径的开通/状态/撤销接口、密钥、
  超时、重试上限、交付面板及可选稳定 instance ID。只读探测调用 plan-catalog，
  有 instance 时还检查 v2 capability；不创建订阅、不撤销、不修改容量。
  instance 必须已存在且 origin 一致；更换站点必须使用新的实例身份。
  新任务与免费流量重置操作在业务事务中固定版本，旧任务的开通、查询、对账、
  强制撤销、退款撤销使用原版本。停用仅停止接受新任务，后台定时器继续处理历史。
  面板地址只用于该版本任务的交付，不改写已有交付。

升级前的履约任务没有端点证据。首次激活会将当前环境底座冻结为历史引导版本，
已有未绑定任务始终解析这份冻结配置，不会随新活动指针切换。如果存在历史任务，
管理员必须先核实环境配置确实是它们原来的目标，再勾选确认；无法确认或原配置
缺失时，系统拒绝切换。不能为了绕过拒绝，把新目标写进旧环境变量。
该确认是历史证据缺失时的人工核验，不会调用远端或修改订单、积分。

容量与账号查询缓存、in-flight 合并按配置身份隔离。不同 API 实例的下次请求会读取
数据库中的活动指针；没有进程级配置文件写入或重启要求。部署的 Xboard 功能灰度
开关、流量重置派发安全开关、确认签名密钥仍由运维管理。

单个历史版本无法解密时，开通、撤销和对账批次记录 `CONFIG_UNAVAILABLE`，
将无活动租约的任务延后 5 分钟重试，继续处理其他版本。不会更换任务绑定、
扣除重试次数或操作远端。管理员应恢复对应根密钥；恢复后按原版本继续执行。

## 第二阶段：支付商户与历史凭据

支持 Stripe、PayPal、微信支付、支付宝和 VMQFox。每个渠道一个当前接受新订单的
账号；可以切换商户，旧账号和所有凭据版本保留。稳定账号身份与凭据版本分开存储；
报价、订单、attempt、验签事件及对账批次分别记录版本，事件去重不使用凭据版本。
报价后发生激活/回滚会要求重新报价，下单与配置切换使用同一个事务锁边界。

先在部署中设置充值环境、币种、安全限额、事件加密密钥和 HTTPS 回调公开 origin。
`RECHARGE_MODE`、`RECHARGE_ACCEPT_NEW_ORDERS` 是部署总开关，后台渠道开关不能越过它们。
新安装可保持 `PAYMENT_ENABLED_PROVIDERS` 为空，激活的数据库渠道会自动出现在可用
支付方式中；不用再把业务凭据同时写入 env。正式部署不接受后台沙箱账号。

后台填写商户身份与完整凭据组，保存后校验并激活。凭据全部留空表示保留已保存值；
更换商户或应用时必须重新填写，不能把原密钥发送给新目标。渠道 API 使用现有官方
host/HTTPS 约束；VMQFox 使用部署允许的 origin，后台不能扩展 allowlist 或突破金额上限。
Stripe 使用明确的 `acct_...` 商户身份，并只读调用 `/v1/account` 核对密钥归属；
不把旧 `stripe:<mode>:default` 当作任意新商户。PayPal 填写 merchant ID，微信填写
mchid/appid，支付宝填写 appId/sellerId，VMQFox 填写稳定商户标识及允许的站点。
同一稳定账号的身份字段不可重新解释；更换商户应新建身份。

**校验边界：**Stripe 校验会进行上述只读身份查询；其他渠道只完成本地参数、
密钥材料与 capability 校验，不代表网络、商户权限、回调、扣款或退款已经可用。
自动校验不创建真实订单、不扣款、不退款。上线仍需按支付 runbook 完成受控业务验收。

保存草稿后，后台显示该账号的专用回调地址：
`/api/payment/webhooks/<渠道>/accounts/<稳定账号标识>`（微信路径为 `wechat-pay`）。
在第三方商户后台登记这条完整地址，切换新商户时保留旧账号回调。路径只选择候选
凭据，服务端仍必须验签并核对商户与交易，不能凭路径或未验签 body 入账。
轮换保留最多 **8 个凭据版本/物理账号**供有界验签；第 9 次激活会拒绝，不能删除
旧版本来绕过。当前没有自动退休版本流程，需要独立升级支持后再继续轮换。

停收新订单后，已绑定版本的创建恢复、complete/capture、查询、关单、退款、争议和
对账继续运行，迟到回调仍沿用原 Observation → applyConfirmedPayment → Credit 入口。
回滚不改写任何已有订单绑定。不要停掉支付 worker 或移除旧账号回调来“禁用”新收款。

**升级兼容：**历史 `providerCredentialRevisionId = null` 的订单继续使用原环境 adapter，
旧 `/api/payment/webhooks/<渠道>` 路径也只服务该环境账号。保留这些渠道的
`PAYMENT_REGISTERED_PROVIDERS` 和原环境凭据，直到历史交易、退款、争议和对账窗口
结束并完成核查。不要将旧环境账号改为新商户；新增和后续交易使用后台版本。
数据库配置损坏或解密失败会报不可用，不静默切回环境凭据。

## 集成根密钥轮换与恢复

先备份数据库与独立保管的原根密钥，给所有实例部署新 current key 和旧
`INTEGRATION_CREDENTIALS_ENC_KEY_PREVIOUS`。对每个服务调用带 `expectedVersion`
的管理员 `POST .../config/rewrap`：短链路径为 `/api/admin/integrations/shortlink`，
履约为 `/api/admin/integrations/faka-bridge`，支付为
`/api/admin/integrations/payments/<渠道>`。

重包在单一事务中覆盖草稿与**全部保留版本**，包括履约历史底座、回滚版本和支付
非活动账号。任一版本无法解密则整体回滚；成功后控制版本递增，草稿测试失效。
只允许修改历史版本的密文字段，不能改业务参数、版本身份或业务绑定。
确认全部服务重包成功、抽查历史查询与恢复演练后，才移除 previous key。
恢复备份时必须同时恢复对应根密钥，单独恢复数据库不能恢复服务凭据。
