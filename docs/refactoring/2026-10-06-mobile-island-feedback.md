# 移动端业务反馈上岛与搜索展开优化

范围：`<768px` 的现有移动导航。实现于 `fix/mobile-detail-sticky-tabs` 整合工作区。本轮不改后端契约、支付/续期计算或数据库。

## 已接入的反馈

- 续费：确认前保留标准结算面板；移动端结算替代原订单详情，提交时让出导航。服务端成功后显示“订单已创建，开通中 / 待交付 / 已交付”，入口指向新订单。失败恢复结算及原结果码处理，桌面继续使用 SuccessModal。避免两层 Radix Dialog 同时恢复造成焦点与 aria-hidden 冲突。
- 订单通知：沿用现有实时事件矩阵、精确 ID 去重与失效刷新。买家/商家订单动态提供操作入口；同单更新合并，商家多笔新单汇总。补齐 `/merchant/orders` 与 `/merchant/orders/:id` 的页面定位。
- 签到：展示服务端积分增量、基础奖励与等级加成，可进入积分流水；不推算连续签到天数。桌面保留原成功提示。
- 弹窗完成：头像保存、评价、订单操作、商家发货/进度/争议处理及库存导入等成功反馈等待实际 overlay 卸载。仍有父面板时，700ms 后使用可见横幅；复制与错误仍即时反馈。

## 展示与身份边界

`notification` / `points` 使用 ActionIslandNotice。支付拥有最高优先级；用户操作完成反馈优先于邮箱/普通公告等被动提醒，其他业务活动最多保留 4 条待展示项。排队项在导航可用时间累计 30 秒后失效；搜索、弹窗及后台标签页的遮挡时间不计入。队列满时优先保留操作完成结果，同优先级保留较新的结果，并按保留下来的先后顺序展示。按 notice ID 收起，旧计时器不能清除新消息。搜索、弹窗、后台标签页与键盘/鼠标交互期间暂停当前活动倒计时。账号/会话变化或离开 Layout 时清空活动与回调。

通知展示、超时与收起均不标记已读。点击单笔通知后才调用已读接口；汇总入口不批量已读。通知跳转使用已知应用路由。争议警告仍为 warning；即时交付、未知事件、重连和校准保持原静默规则。

## 搜索卡顿修复

原搜索态移除了导航的固定占位，分类行又用 `max-height` 动画持续撑高导航；ResizeObserver 将变化写回全局导航高度，同时卡片启用大范围背景模糊。

现在所有移动 chrome 状态保留 `65px + safe-top` 占位。搜索绝对定位覆盖页面，使用实心背景，内容只做 opacity / transform 动画；分类仍可横滑。导航高度写入去重，搜索下沿单独提供给 fallback toast。聚焦使用 `preventScroll`，输入法组合中的 Enter 不关闭搜索，Escape 和遮罩可关闭；支持 reduced motion。

同一 Chromium、390×844、4 倍 CPU 降速，重复展开的两次稳定样本：

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| LayoutCount | 20、21 | 2、2 |
| 导航高度范围 | 65–134px | 65–65px |
| 根样式变更次数 | 4、4 | 1、1 |

这是本地浏览器对比，并非真机帧率承诺。完整三次样本、截图和脚本保存在下述验证目录。
