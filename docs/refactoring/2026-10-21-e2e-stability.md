# E2E 稳定性修复（2026-10-21）

基于 `develop` 的 `3544a9ae6757b5b5cf288aa7f2d13ad924496b26`，集中处理
主浏览器套件的相册重试、通知条件跳过，以及商品运营的几何采样问题。

## 相册：测试会话被未模拟的 API 请求清除

相册使用 `createMockAccessToken` 生成未签名的 UI 测试令牌，原路由模拟允许
未覆盖的请求继续访问后端。新增的推荐读取会经过可选身份认证；真实后端拒绝
该令牌后，客户端可能刷新会话、登出并重新加载商品，将活动图片重置为第一张。

在隔离 Vite 与返回 401 的本地 API 模拟服务中，临时诊断在滑动后留出响应完成
窗口，连续两次记录到登录状态变为 false，且主图回到第一张，与 CI 失败相符。
该诊断等待只用于复现，未加入正式测试。

修复补齐推荐、商品模板与法务开关响应；未覆盖的 API 请求中止并明确报错。
拦截范围只匹配 pathname 以 `/api/` 开头的请求，保留 Vite 的 `/src/api/`
源码模块加载。移动滑动通过 Chromium 原生触摸输入执行，覆盖命中测试及
`touch-action`，保留完整图片与切换结果断言。

## 通知：CI 与本地功能开关不一致

主 CI 栈没有设置 `NOTIFICATION_ENABLED`，使用默认 false，导致六个通知场景
收到 404 后跳过；本地 Playwright 栈则设置 true。CI 现在显式启用站内通知并
关闭邮件通道。通知场景把功能未开启视为配置失败，不再跳过。

跨用户已读测试自行创建人工订单及商家通知，按订单定位通知，消除对其他测试
留下数据的依赖。数据读取或生成失败直接使断言失败。

## 商品运营：在同一帧读取商品行几何

PR #262 首轮记录的名称/状态交叠约为 1.19px。切到移动视口会启动页面入场
动画，原四次独立 `boundingBox()` 操作可能跨帧读取一起移动的单元格。
此前静态 DOM 实验没有重现原失败，不能把该采样风险当作已证明的唯一根因。

现在在一次同步 DOM 操作中读取全部矩形，消除跨帧比较；可见性、三组不交叠和
视口边界断言继续执行，未添加交叠容差、固定等待或额外重试。
