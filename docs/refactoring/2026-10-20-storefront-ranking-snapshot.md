## 核对与修复

- 热卖投影明确读取快照的 `isHot`；只有该标记成立才返回 hot 块，快照存在和订单
  数量本身都不能替代这个判据。平台自营与热卖身份相互独立。
- 留存清理使用独立舰队租约，按约每小时的窗口调度，不依赖排行计算是否已注册或
  成功；成功释放互斥，失败回拨窗口以便下个 tick 重试。既有 SQL 保留最新完成的
  排行，清理过期的旧排行及快照，另按既有期限保留失败诊断。
- 商城 API 提取合并候选商品详情请求并保持失败降级；搜索模式不注入推荐候选。
  游标过期时清空列表、去重和组合状态，最多自动重取首页一次；普通追加失败保留
  列表并暂停该游标的自动加载，显式点击仍可重试。分类注册表失败可重新加载。
- **本轮新增修复**：单独启动留存调度器后，`stopRankingCron()` 原先会因排行
  timer 不存在而提前返回，遗留留存 timer。现在先停止留存调度器，再处理排行
  timer。回归使用真实调度入口和 fake timers，替换原先被 test 环境短路的空操作
  检查，覆盖重复启动、统一停止、重新启动及独立留存启动后的统一停止。
- **本轮新增集成断言**：旧排行保留时旧游标继续有效，且非热商品 hot=null；执行
  真实留存 SQL 后，旧排行及其快照被删除，原游标返回 409
  `PRODUCT_CURSOR_EXPIRED`，不带游标的首页使用新排行并正常返回热卖投影。

本轮相对开始时只修改上述 cron 实现、留存回归、商品集成回归三个源码文件；其余
生产改动均沿用主工作区现有内容。历史交付清单仍保留原始 12 路径分类，本轮新增
的商品集成回归显式纳入这份 13 路径快照。
