## 已确定的用户需求

1. MoNexus 注册邮箱可能与 Xboard 邮箱不同，禁止用二者相等作为关联前提。
2. 目标用户已经在 MoNexus 购买过 Xboard 套餐。正常成功订单及已有邮箱归属证明可恢复关联，不要求这些用户重新绑定 Xboard 邮箱。
3. QQ 与 MoNexus 的既有绑定继续使用；新增功能从可信 QQ 发送者解析站内用户。
4. 符合条件的用户赠送一次流量重置机会，之后通过正常购买获得重置。
5. 用户可以查询套餐剩余流量及重置次数。可用机会和历史执行次数分别展示。

## 本方案采用的默认业务规则

以下默认业务规则已经用户批准；B2 两端已实现并通过本地定向验证，开关默认关闭、未部署，不能视为已对用户生效。

- 赠送按 **MoNexus 用户终身一次**，不是每个订单、套餐、邮箱或 QQ 各一次；换绑不刷新。
- 赠送面向已有符合条件的成功套餐购买者；上线前历史回填，新订单在成功交付时发放。
- 一名用户关联多个 Xboard 账号时共享这一份机会；第一次需要选择账号，之后记住默认选择。
- 免费重置由用户明确确认触发，不在下单或领取机会时自动执行。
- 免费重置只作用于当前有效订阅；不新建 Xboard 用户、不购买新套餐、不延长到期时间、不增加套餐总流量。
- 免费用完后的 V1 购买入口跳转本站对应重置商品，沿用现有报价、下单及履约；机器人 V1 不直接扣积分下单。
- 流量返回面板当前记录和查询时间，承认节点上报延迟；查询失败不显示为零。
- 首屏性能优先：候选在普通商品首批提交前已准备好时正常混排；迟到时本次展示普通流，迟到结果不替换已展示卡片。

最后一条涉及现有 `SPEC-CMI-UX-001` 的首 12 槽固定混排规则修订。方案将其作为显式产品变更描述，未把它冒充为纯技术重构；严格保留原规则的备选路径见性能方案。

## 实施顺序与交付边界

| 阶段 | 工作与主要触点 | 验证及退出条件 |
| --- | --- | --- |
| P0 基线 | 固定工作区版本、Node 22/npm 10、浏览器与夹具；补入口依赖闭包统计、首批商品可见标记、RUM 出口核验 | 记录基线产物与 HAR/trace；把现状、目标、未测分开 |
| P1 首屏 | `App.tsx` 路由懒加载；首页首次/分类立即请求；搜索防抖与请求取消；首屏图片优先级、去 reveal 延迟；9 键配置批读 | 页面直接访问与鉴权回归；无首次 300 ms 人为等待；配置默认值一致 |
| P2 商品数据 | `/api/storefront/candidates`；服务端批量卡片读取；前端一次提交策略、缓存及 audience 隔离 | 无逐候选详情 HTTP；推荐故障不挡商品；无丢项、重复、跨受众缓存 |
| P3 媒体与持续性能 | 图片变体、历史图片分批处理、字体自托管、不可见动画停帧；按观测调整动态投影缓存 | 新旧图片兼容；资源和首屏指标复测；索引变化有执行计划支撑 |
| B0 插件能力 | 对齐实际部署的 Xboard 核心和 FakaBridge 版本；能力探测；签名 v2；身份解析与套餐查询 | 插件迁移安装流程在隔离环境验证；不使用上游 master 代替部署版本 |
| B1 账号与查询 | MoNexus 关联表、历史扫描/回填、默认账号、机器人流量和次数查询 | 正常老用户无重新绑定步骤；异常清单可核对；查询不会修改套餐 |
| B2 赠送与执行 | 权益、确认意图、独立 reset outbox；插件幂等执行及状态接口；重试与对账 | 并发只能消费一次；远端成功/本地超时不二次重置；未用权益正确释放 |
| B3 付费入口与灰度 | 当前套餐重置包购买链接；部署机器人适配器；内部账号到小范围用户灰度 | 网站购买链路不变；真实 QQ 会话完成查询、确认、处理中、成功/失败路径 |

P1 与 B0 属于不同工程模块，可在各自验证后独立交付。P2 依赖商品批量接口和前端协议共同完成；B2 依赖插件与 MoNexus 两侧都就绪。图片变体不是查询或赠送功能的前置条件。

## 发布、观测与回退

- 性能 PR 按阶段独立，先建立 baseline，再比较相同数据、设备和网络条件下的结果；不通过提高预算阈值来隐藏回归。
- 新候选接口保留旧接口兼容期；前端可回退普通商品流，候选故障不恢复整页等待。
- 机器人开关拆为查询、新赠送发放、接受新重置请求；停止新请求后，对已提交操作继续对账。已有权益、操作与幂等记录保留。
- 插件先部署兼容性新增接口和表，再部署 MoNexus 查询、回填、重置，最后升级 QQ 适配器并开启写操作。
- 数据库迁移使用增量方式；回退应用不删除已应用表、不清除已消费权益或远端成功记录。
- 本次不执行任何生产动作。正式实施沿用现有分支、CI 和部署流程；验收按 [testing-policy.md](../../testing-policy.md) 分层，数据库测试只能使用可丢弃测试库。
