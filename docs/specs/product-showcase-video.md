# 商品展示视频实施方案

文档 ID：SPEC-PRODUCT-VIDEO-001；版本：0.1；日期：2026-10-22。

状态：已在独立 worktree 完成本地实现，未发布。实施基线、验证证据和未完成的生产验收见[运行说明](../operations/product-video.md)。下文“当前”“本轮”涉及的代码现状保留为设计时快照，不代表实现后的状态。本文单独管理视频范围，不修改《分类游客可见性与人工公开准入实施方案》v0.2；双方共同实施时，以本文列出的接缝补充视频规则。

## 1. 推荐结论与本期范围

建议增加商品详情主图库中的可选展示视频，每件商品最多一个。商家和管理员可以上传、预览、替换、移除；桌面、平板、手机共用播放器。列表继续展示封面图，用户点击后才获取短时播放地址和下载视频字节。

视频可以与 P1/P1.5 并行开发，使用独立分支和 worktree；视频生产开放依赖 P1/P1.5 的统一门禁及公开批准失效规则。BOT 止血仍最先发布，P1 与 P1.5 同批上线。视频验收晚于它们时独立发布，不延迟权限修复。

首版采用现有私有对象存储、流式上传、受限媒体探测及 MP4 封装整理、原生 HTML video。暂不建设完整转码队列、多清晰度、HLS/DASH、断点续传、视频外链抓取、富文本嵌入、自动播放、AI 视频审核、播放统计平台或付费视频交付。

本文的时长、大小、配额和超时均为建议默认值，尚未做生产机器容量实测。实施时通过一次小范围技术验证确定部署可承受的具体配置，不因播放器能显示就视为全部完成。

## 2. 当前能力与依据

### 2.1 当前项目不支持商品展示视频

Product 目前只有 imageUrl、images 等图片字段，没有视频引用。图片上传使用内存 Buffer，限制图片格式和 5 MiB，前端还经过裁剪；不能只给文件选择器加上 video/mp4。图库和图片灯箱也都是图片语义。

富文本渲染和粘贴明确移除 video/audio。首版保持这条边界，视频从独立字段进入主图库，不放开任意 HTML、iframe 或外部播放器。

现有付费文件交付支持流式私有上传，但签名强制 attachment 与 application/octet-stream。它可以提供实现模式，不能原样当作在线播放接口。

### 2.2 规模与证据边界

既有方案记录的 2026-10-21 生产只读查询结果为全库 15 件商品、public 0 件；该记录来自对话中先前回传的生产 SSH 查询结果，本轮未直接连接生产。它说明应采用小规模方案，不代表本轮核实了商品数量、视频需求量或现时服务器余量。

本轮本地分支为 fix/merchandising-hot-badge-projection，HEAD 为 56791c3，工作区有大量既存修改及未跟踪文件。本文代码依据是该工作区快照，未声称本地与最新远程对齐；实施前必须重新核实远程交付基线和未提交重构的归属。

## 3. 产品行为与文件限制

### 3.1 商家和管理员

展示信息区增加“商品视频（可选）”。上传前说明格式、时长和大小；上传中显示真实字节进度，传完后显示“校验处理中”，不能将传输 100% 显示成已保存。成功后可预览、替换、移除。

上传成功只生成待关联资产，不自动修改商品。用户点击保存商品时才关联；放弃编辑不会影响原视频。替换失败保留旧视频；保存发生版本冲突时要求刷新，不覆盖他人刚修改的视频或内容。

移除视频通过商品保存完成，界面明确提示“公开商品的视频变化需要重新审核”。members_only 商品仍可面向有权限的登录用户展示，不要求先获游客公开批准。

平台管理员创建商品也不默认获得游客公开资格；编辑权限与公开批准权限沿用现有管理规则。

### 3.2 建议默认限制

| 项目 | 首版建议 |
| --- | --- |
| 每件商品 | 0 或 1 个展示视频 |
| 文件大小 | 不超过 40 MiB，即 41,943,040 字节，服务端独立计数 |
| 时长 | 大于 0 且不超过 60 秒，依据服务端媒体探测与解码验证 |
| 尺寸 | 正常显示方向下长边不超过 1920、短边不超过 1080；支持横屏和竖屏 |
| 封装与画面 | MP4、H.264、8 位 yuv420p；首版拒绝 HEVC、AV1、HDR 等未验证组合 |
| 音频 | AAC-LC 或无音轨；最多一条视频、一条音频，立体声以内 |
| 帧率 | 有效探测值不超过 60 fps；异常或无法确认的输入拒绝 |
| 外链及嵌入 | 不接受外部视频 URL、远程抓取或富文本播放器 |
| 商家配额 | 建议最多 5 个未关联 ready 资产；每个归属主体最多 1 个正在上传/处理的资产 |

容器扩展名和浏览器 MIME 只是提示，不能替代真实格式验证。旋转信息、像素长宽比、可变帧率及 AAC 兼容性需用真实文件验证；支持不了的组合返回固定转格式指引，不悄悄放行。

40 MiB 和 60 秒并不保证清晰或流畅。建议商家导出为 720p 或 1080p、约 2—5 Mbps、普通 SDR MP4；推荐参数属于使用指引，实际仍按服务端接受条件判定。

### 3.3 访问者体验

商品封面和图片顺序不变，视频入口放在图库第一个媒体位置，用现有封面加播放标识展示；初始不自动播放，也不请求视频字节。列表、推荐、榜单、分享预览仍使用原有图片，不额外分发视频地址。

用户点击视频后请求播放凭证，再将地址交给原生 video，启用 controls、playsInline、preload=none。初始不设置视频 src，避免把 preload 提示误当成绝对禁止下载。首版默认静音，可主动打开声音；切换媒体、离开详情、退出登录或账号切换时暂停并移除 src，释放当前播放资源。[video 元素官方说明](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/video)

视频支持暂停、进度拖动、音量和浏览器原生全屏。已有图片灯箱继续仅服务图片，视频不塞进图片灯箱，避免把图库导航、缩放与全屏播放混在一起。

加载、解码、签名过期或网络失败时保留封面和图片切换，显示“视频暂不可播放，可重试”，不能阻塞详情和购买。提供可键盘操作的播放按钮、清楚的状态文案；首版没有字幕编辑器，不宣称已满足所有视频无障碍要求。

## 4. 与 P1/P1.5 的统一权限规则

### 4.1 播放授权矩阵

| 请求情形 | 是否签发播放地址 |
| --- | --- |
| 游客，商品 public、分类允许、生命周期满足且当前公开版本已批准 | 允许，限该商品当前视频 |
| 游客，members_only、分类受限、待审、拒绝、撤销或批准版本过期 | 拒绝，不含视频信息或 URL |
| 普通有效登录用户 | 按统一 member 商品访问规则；公开批准不额外限制 member |
| 已停用账号、无效会话 | 不授予 member，按既有认证规则处理 |
| 商家或管理员在编辑器预览未发布视频 | 走单独的归属/管理授权，不借用公开商品接口 |
| 下架、归档或商家不可用 | 普通商品播放拒绝；具有编辑权限的预览另行判定 |

每次签发都从数据库确认商品当前访问资格和当前视频引用。Redis 命中、客户端 audience、自称管理员、旧商品 DTO 或知道 assetId 都不能替代授权。PG 不可用返回错误；不回退旧公开缓存，不改发永久 URL。

### 4.2 公开批准绑定完整视频版本

视频新增、替换、移除均属于展示内容变化，在同一个商品写事务中更新引用、递增 publicContentRevision、将准入重置为 pending。重复提交相同引用不构成变化；仅上传而未关联不改变商品版本。

原 contentVersion 继续用于编辑 CAS；publicContentRevision 用于公开审核；eligibility.version 用于审批操作 CAS。三个版本职责不同，不合并，也不复用 expectedCheckoutVersion。

管理员审核时需能够完整播放当前视频并听取音频，画面内字幕、二维码及口播都属于人工判断范围。缩略图或抽取一帧不能代表已审视频。审核页面展示视频资产标识及公开版本，批准仍提交两个 expected 值；替换视频后旧页面批准必须返回 409。

若需要检查尚未关联的资产，只通过编辑预览接口；它不能成为面向游客的播放捷径。首版不接 Jev 或其他 AI，未来文本分类模型的通过结果也不能自动覆盖视频和音频。

### 4.3 短时链接的实际边界

建议播放签名有效期 180 秒；播放凭证 JSON 和对象响应均设置 private, no-store，并对查询参数及日志做脱敏。签名 URL 是临时持有者凭证，在有效期内可被复制和转发。[S3 预签名 URL 官方说明](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)

退出登录、分类收紧、撤销批准会阻止新签发，前端主动停止当前播放；已签发的链接不会因此立即失效。过期也不保证中断已建立的传输或撤回已下载字节。若以后要求每个字节请求即时检查身份，需要另外设计媒体网关，不能用本方案声称已经实现。

本方案也不提供 DRM 或防录屏。现有图片仍沿用 P1 的 URL 非分发边界，不借新增视频功能迁移全部历史图片。

## 5. 数据模型与不可变资产

### 5.1 建议最小模型

| 对象 | 建议字段与约束 |
| --- | --- |
| Product | promoVideoAssetId 可空外键，唯一；每商品最多一个视频，每资产最多关联一个商品 |
| ProductVideoAsset | id 为不可预测标识；merchantId 可空，空表示平台归属；createdById 记录上传者 |
| 资产媒体引用 | videoStoredObjectId、posterStoredObjectId；ready 时两者必须存在且属于 private/product_video |
| 资产媒体信息 | durationMs、width、height、hasAudio、status、createdAt、updatedAt |
| 资产状态 | uploading、ready、failed、deleting；状态失败不等于商品审核拒绝 |
| StoredObject | 复用 providerConfigId、bucketRole、objectKey、size、checksum、mimeType；source 新增 product_video |

不把临时 URL、供应商密钥或任意外链写到 Product。存储位置由 StoredObject 绑定，每次读按该绑定解析，不能因为全局 active provider 改变就改读另一个桶。

merchantId 判断所属经营主体，createdById 只是审计来源；管理员代商家上传时资产仍归该商家。普通商家不能把自己的资产关联给他人商品，也不能认领平台资产。

新建商品前允许上传未关联资产。初次关联时，在商品事务中校验归属、ready、未关联和对象完整性。平台预览和商家预览各走相应权限，不向无权用户暴露资产是否存在的差异。

### 5.2 不可变与关联竞态

每次成功上传生成新资产、新对象 key；即使文件相同也不跨商品去重。首版用少量额外存储换取清晰的归属、权限和清理关系，避免同一视频被多个商品复用后难以撤销。

ready 资产的视频、海报、媒体信息和物理位置不允许原地替换。换文件创建新资产，再用商品保存替换引用。存储管理员迁移不在本期，不能通过改 provider 元数据偷偷换批准内容。一次上传开始时固定写入 provider 配置快照，视频与海报使用同一绑定；上传期间切换 active provider 不改变这次写入目标。

关联或解除关联刷新资产 updatedAt，用于未引用宽限期。写事务沿用 Product 行锁，随后按资产 ID 稳定顺序锁定新旧资产；审批只锁商品。唯一外键阻止两个商品并发抢占同一资产，版本冲突或已被占用返回 409。

老接口省略 video 字段表示保留，显式 null 表示移除；只在支持该字段的契约中解释 null，不能把旧客户端未传字段当成删除。导入/上游同步不擅自清空本地视频；新增导入商品默认无视频。

## 6. 上传、验证与处理流程

### 6.1 同步有限处理

首版不建持久队列。单个工作进程最多执行一个上传/处理请求，忙时立即返回 429 和 Retry-After，不在内存里无限排队。多实例扩容前重新评估容量与全局约束，不提前建设共享熔断或租约系统。

流程为：校验会话与经营权限 → 原子占用该归属主体上传名额并创建 uploading 记录 → 流式写入隔离临时目录且计数 → ffprobe 探测 → 有界解码验证 → 封装整理及生成海报 → 将规范化 MP4 和 JPEG 流式写入私有存储 → 同事务登记 StoredObject 并将资产置 ready → 返回资产 DTO。主体配额通过 PG 事务内主体锁和计数执行，不能先查询数量再无锁插入；进程并发上限另由本地信号量约束。

临时文件替代 Node Buffer 全量持有。原始文件不永久保留；只保留最终 MP4 和海报。封装整理使用视频/音频 stream copy 和 faststart，不承担任意编码转码；不能以改扩展名冒充格式转换。丢弃未选择的字幕、数据轨和不需要的元数据；保持合法旋转和显示方向，无法保真处理时拒绝。整理后再次核对时长、媒体参数、可解码性和 40 MiB 上限；超限不置 ready。[FFmpeg MP4 封装说明](https://ffmpeg.org/ffmpeg-formats.html#mov_002c-mp4_002c-ismv)

海报从有效画面生成，限制尺寸和输出大小，存入同一私有命名空间。详情初始用现有商品封面，避免为了海报提前签发视频 URL；编辑器及审核页可以通过授权预览获取该海报。

### 6.2 资源和安全限制

建议整个请求硬超时 240 秒，其中接收上限 120 秒，媒体探测/解码/封装累计 60 秒，最终对象写入累计 60 秒；各步不能把总超时重新起算。进度要区分上传与处理，超时清楚提示重试。

ffprobe/ffmpeg 通过固定参数数组启动，不使用 shell、不拼接用户文件名，不接收远程 URL；只允许所需本地协议。隔离用户目录、非 root 执行，设置进程时间、CPU/内存与临时盘限额；限制输出日志长度并保持二进制安全更新。拒绝外部引用、异常轨道、不可解码和资源预算超限文件。

建议临时盘至少预留 512 MiB 作为起点，覆盖输入、封装输出及处理中余量；最终以实际工具峰值验证。磁盘不足、客户端中断、进程退出、对象上传失败和 DB 提交失败均进入清理路径，不把不完整文件置 ready。

HTTP 传输完成而响应丢失时，上传可能已成功；用户重试会创建另一资产，首版由配额和未关联清理约束残留，不引入断点续传或完整幂等任务系统。

### 6.3 失败与重启

请求存活时失败立即中止子进程、取消 multipart、尝试删除本次对象及本地临时文件，并记录有限错误码。失败资产不可关联。

服务重启后没有可恢复后台任务。超过请求硬超时并加宽限的 uploading 记录由定时清理标记 failed，释放名额；下次用户重新上传。残留对象依靠资产命名空间扫描和宽限期处理，不能依赖进程内 finally 保证永不遗留。

ffmpeg 缺失时健康检查标记视频上传不可用，视频上传返回明确 503；已有视频、图片和购买流程继续工作。对象存储故障时不发无效地址，用户可继续看图片。

## 7. 存储、清理与备份

### 7.1 推荐使用现有私有桶的专属命名空间

首版不增加第三种桶配置和新的存储控制台。使用当前 private bucket，目录固定为 product-videos/v1/{assetId}/video.mp4 与 poster.jpg；只有服务端构造 key，客户端只能提交 assetId。

这个选择成立的硬前提是先修改付费附件 GC：它目前枚举全部非 tmp 最终 key，再只看 DeliveryFile 引用。仅增加前缀、登记 StoredObject 或新增数据库表都不能保护视频。

付费附件 GC 必须只接管已知付费附件命名规则或其显式登记对象，并保留其原有共享引用复查和锁；明确跳过 product-videos/、探测和未知 key。未知对象只记录诊断，不扩大删除范围。不能为修视频而误伤历史附件。

如果基线盘点发现无法可靠区分历史附件范围，则停止共享桶方案，单独评审视频桶配置及备份、代理变化；不得带着误删风险先上线。

### 7.2 视频生命周期与竞态

未关联 ready 资产在最近上传或解除关联后保留 24 小时；failed 和过期 uploading 记录也按有界宽限清理。商品关联中的资产不因年龄删除，归档商品仍有引用时同样保留。

清理任务按资产查询，不对整个桶任意删除。先锁资产、复查没有 Product 引用且宽限已过，将其标记 deleting 并提交，再在事务外删除对应视频和海报；成功后标记 StoredObject deleted 并删除资产记录。删除失败保留 deleting 供下次重试，不能先丢失物理对象清单。

商品关联事务锁资产并要求 ready；清理已抢先改为 deleting 则拒绝关联。清理不能再反向等待 Product 行锁，避免与商品写入形成锁序循环。另以外键和并发集成测试兜底。

物理上传后、DB 登记前崩溃形成的孤儿，只在 product-videos/v1/ 严格 key 范围内扫描；超过 24 小时后按 assetId 查询数据库，存在引用、进行中记录或查询故障时一律保留。即使没有 List 权限，正常上传/播放也可工作，但上线必须提供可执行的孤儿回收方式，不能无限积累。

### 7.3 备份与恢复是首版范围

现有 portable backup 私有对象筛选只接受 hash.extension，不会收录视频目录。必须增加独立的视频 manifest 项，依据资产及绑定的 provider 逐项收录 MP4、海报、大小、校验和及关联；不能只遍历当前 active provider。

数据库快照与对象 manifest 必须对应同一批资产版本；备份过程中对象变化或缺失则明确失败并重试，不能生成无法恢复的“成功”备份。恢复时同时恢复数据库引用和对应物理对象，校验大小/校验和及 MIME，并拒绝路径穿越、任意桶路径和未授权 key。目标 provider 与原 provider 不同时，按受控恢复映射一致重建 StoredObject 绑定，不把新恢复对象指向原环境地址。

视频对象导出与导入使用流式文件处理，避免把多件视频累积为内存 Buffer。备份格式须能识别新增类型，旧备份恢复后无视频仍可正常打开；旧版工具遇到新格式应明确拒绝，不能静默丢视频后报告成功。

至少完成一次“上传关联 → 备份 → 隔离环境恢复 → 授权播放”的演练，并验证历史付费附件照常恢复。现有全量磁盘备份可作为补充，不能替代对便携备份缺口的处理。

## 8. API 与 DTO 草案

### 8.1 上传和编辑

| 方法与路径 | 契约 |
| --- | --- |
| POST /api/uploads/product-video | multipart 单文件；校验经营主体权限，成功返回 assetId、媒体信息、ready；不返回永久 URL/key |
| GET /api/merchant/product-videos/:assetId/preview | 仅本人经营主体资产；返回短时视频与海报预览凭证 |
| GET /api/admin/product-videos/:assetId/preview | 现有 active admin 及相应管理权限；不授予游客商品访问权 |
| 现有 POST /api/merchant/products、/api/admin/products | 支持 promoVideoAssetId；默认 null，关联 ready 资产 |
| 现有 PATCH /api/merchant/products/:id/content 及 admin 同类接口 | 可选 promoVideoAssetId；省略保留、null 移除，要求 expectedContentVersion |

管理员代商家上传时需明确 merchantId 并核实管理权限；商家路径从登录身份推导 merchantId，拒绝请求体越权覆盖。上传与预览不扩大现有角色权限，管理写入的 MFA/CSRF 约束沿用项目规范。

建议固定错误：413 VIDEO_TOO_LARGE、422 VIDEO_FORMAT_UNSUPPORTED / VIDEO_DURATION_EXCEEDED / VIDEO_INVALID、429 VIDEO_UPLOAD_BUSY / VIDEO_ASSET_QUOTA、409 PRODUCT_CONTENT_CHANGED / VIDEO_ASSET_UNAVAILABLE、503 VIDEO_PROCESSING_UNAVAILABLE / VIDEO_STORAGE_UNAVAILABLE。错误不得带原始 ffmpeg 输出、私有路径、存储配置或签名。

### 8.2 商品播放

GET /api/products/:id/video-playback 只签发该商品当前关联资产。请求可带 expectedVideoAssetId，若与当前引用不同返回 409 PRODUCT_MEDIA_CHANGED，要求刷新详情，避免旧页面误播新内容；不能请求一个任意 assetId 后绕开商品访问规则。

成功返回 videoAssetId、playbackUrl、expiresAt 及必要媒体信息；必要时含同期限的 posterUrl。地址在签名中固定 Content-Type=video/mp4、Content-Disposition=inline 和缓存指令；保留付费附件原有 attachment 语义。

现有详情 DTO 增 promoVideo: null 或 { assetId, durationMs, width, height, hasAudio }，不含 provider、bucket、objectKey、原始文件名和永久视频/海报 URL。只有通过商品门禁后的详情能返回；列表仍不增视频地址字段。

拒绝时使用统一商品访问错误契约：未登录需要登录返回相应固定 403 状态，其他无权/不存在按既有规则处理。响应只含通用 code/message，不附商品名、视频元数据或 URL。编辑预览接口不可与普通商品接口混用。

签名 JSON 不进 service worker 或持久缓存，前端不把地址放 localStorage、全局商品缓存、埋点或错误上报。新字段加入后递增相应 DTO/cache namespace，避免旧投影继续返回不匹配引用。

## 9. 前端数据链与播放生命周期

商家创建的 PresentationStep、管理员新建向导、共享 ProductInformationSection 复用独立 ProductVideoUploader；不改变图片裁剪上传器语义。更新 CreateProductV2Input、请求 builder、editorForm、saveProductEdits、编辑 DTO 与 API 类型。

图库内部从 images 字符串数组提升为带 type 的媒体条目，图片沿用原有 SafeImage 和 lightbox。视频切换需要独立组件，媒体类型切换后同步缩略图、索引、计数和键盘控制；不能让“第几张图片”把视频计入图片灯箱索引。

播放凭证请求使用 AbortController 加访问代数，绑定 productId、assetId、身份代数；A→B→A、登录/退出、同商品视频更换及旧 play Promise/媒体事件晚到，都不能写回当前页面。身份变化主动清 src，不能只清 React 商品缓存而继续播放旧链接。

过期后用户继续拖动或重试时，最多自动重新授权一次并保留可恢复的播放位置；每次都重跑门禁。若权限已撤销则停止并刷新详情/登录提示，不循环重签，也不在后台无限续期。

真实媒体事件和网络实现必须验证，不能仅靠 jsdom 中触发 canplay 就宣称 iOS Safari、Android Chrome 和桌面浏览器可播放。

## 10. 部署、容量与故障降级

### 10.1 部署改动

server runtime 镜像目前没有 ffprobe/ffmpeg，需要安装固定、可追踪更新的发行包，并在部署说明记录版本、运行权限和资源限制。新增视频功能健康检查不应把上传处理故障扩大成整站不可用。

Nginx 为 /api/uploads/product-video 单独设置约 45 MiB 的总请求体上限，给 40 MiB 文件留 multipart 开销；关闭请求缓冲并将代理超时与 240 秒应用预算对齐。Node 请求超时、容器入口及生产外层 1Panel/OpenResty/CDN 同步检查，不能只改仓库 Nginx。

在线播放沿用私有桶公共签名入口或 provider 自有 HTTPS endpoint，保留签名覆盖的 Host、路径和查询参数。验证 Range、206、Content-Range、Content-Length、416、签名过期与拖动。跨域 provider 要按实际播放器需要配置 CORS，不用放开整个桶匿名读来解决播放错误。[HTTP Range 官方说明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Range_requests)

对象通路访问日志和错误平台不得保存完整签名查询串；响应头、Referrer-Policy 与 HTTPS 一并核实。对实际生产使用的每个 provider 验证能力，不能把“兼容 S3”当作已通过端到端播放验证。

### 10.2 故障与控制

| 故障 | 处理 |
| --- | --- |
| ffmpeg 缺失、处理超时或进程崩溃 | 新上传失败并回收残留；已有视频与图片可用 |
| 存储不可达或签名失败 | 显示视频不可用和图片回退，不阻断下单 |
| PG 无法确认权限 | 不签发，不用旧缓存放行 |
| 签名过期 | 用户动作时最多重签一次；无权则停止 |
| 临时盘不足或并发已满 | 拒绝新上传，保留原商品和原视频 |
| GC 或备份失败 | 报警并保留对象，不以删除数据自愈 |
| 流量异常 | 按既有网关限流、暂停新播放签发；到期前已有链接仍可能使用 |

允许设置两个简单部署开关：暂停新上传、暂停新播放签发。它们仅用于故障处置，不引入 shadow/enforce 或多版本决策模式；暂停播放时前端自然回到图片。

### 10.3 成本口径

成本主要是实际播放流量，其次是存储、备份和上传处理资源。按平均视频 20 MB、每月 10,000 次完整播放估算，视频本体出站约 200 GB；拖动、重试、预取和流量攻击可能增加，部分播放可能减少。这是用量算例，不是报价。

按 15 件各 40 MiB 的上限算，单份视频约 600 MiB，尚未计海报、未关联资产和备份副本；不以该历史商品量当未来容量上限。首版从现有监控观察上传失败率、处理耗时、临时盘、签发错误和存储出站，不搭建新统计平台。

签发次数不能代表播放次数或实际字节；签发限流也不能阻止一个有效 URL 被多次请求。带宽告警和预算控制应从存储/反代计量落地，不能承诺仅靠 API 限流实现硬费用封顶。首版不选新付费供应商，需另购 CDN 时再按实测量评估价格及签名缓存策略。

## 11. 并行开发、worktree 和职责边界

### 11.1 采用独立工作区，先固定共享契约

P1/P1.5 与视频使用不同 worktree、分支和独立可丢弃测试库。worktree 隔离文件，不隔离数据库、端口、临时目录、对象桶、Redis 或迁移；这些资源也要分别分配，避免测试清表和 GC 互相影响。

建议分支 feat/catalog-guest-eligibility 与 feat/product-showcase-video，均从届时核实的 origin/develop 派生。当前未提交重构先按归属盘点，不能直接以脏工作区为发布基线，也不允许 reset、盲目 stash、整包复制或把无关改动带入视频 PR。

P1/P1.5 交付正式契约后，视频分支吸收所需提交再联调；开发阶段可用契约测试桩，生产不能使用“缺准入逻辑就按 public 放行”的兼容回退。

| 责任 | 归属 |
| --- | --- |
| 分类门禁、四路径等价性、准入表、publicContentRevision、审批 CAS | P1/P1.5 |

### 11.3 合并和迁移顺序

优先合并 P1/P1.5 基础字段、锁和准入失效能力，再合入视频增量模型及适配。视频上传处理、播放器和存储能力可提前开发评审，但不抢写同一份商品写入代码。

视频迁移只新增可空引用和新表，旧商品默认无视频，无历史转换。最终在全新库和已有 P1/P1.5 的测试快照上分别演练迁移；不要把 worktree 的 prisma db push 当作正式生产迁移。

## 13. 验收与测试分层

### 13.1 后端集成与并发

验证真实签名/字节伪装、40 MiB 边界、超时、损坏 MP4、外部引用、异常轨道、尺寸/时长限制、上传中断及两个对象只成功一个的补偿。测试格式 fixtures 要覆盖无音频、竖屏旋转、可变帧率和不支持编码，工具失败不得标记 ready。

权限用例覆盖游客批准矩阵、member、账号失效、跨商家/平台资产、任意 assetId、旧详情引用、未发布商品预览和 PG 故障。确认所有拒绝响应与日志不带视频私有信息。

事务用例覆盖视频替换与批准竞争、旧版 PUT 和新编辑器并发、两商品抢占资产、两次替换、清理与关联竞争、重复相同引用不增审核版本、纯价格不触发视频重审。成功写入必须同时更新引用与撤销旧公开批准，失败则全部回滚。

清理测试至少放入历史付费附件、已引用视频、未引用视频、未知对象、另一个 provider 的对象，确认各自仅由正确清理器处理。查询失败保留对象；删除中断可重试；不能只在内存 storage mock 上测一个 happy path。

### 13.2 前端组件与真实浏览器

组件测试覆盖上传/处理/失败、替换保留旧视频、null 与省略、图库索引、错误回退、暂停销毁、旧凭证/媒体事件晚到、身份切换和过期一次重签。图片灯箱和图片上传的既有回归要保持。

按仓库测试策略，新增至多一条主流程 E2E：“商家上传保存 → 管理员预览批准 → 游客播放”，权限边界与竞态主要放后端集成和组件层。相关鉴权横切改动按要求触发现有全量 E2E，而不是为每条文案新增浏览器用例。

独立做真实媒体兼容矩阵：桌面 Chrome/Firefox、目标 iOS Safari、Android Chrome，覆盖内联/全屏、横竖屏、暂停/拖动和签名过期。自动化项目未覆盖 WebKit 时，需要实际设备或对应引擎验证证据，不能以 Chromium 手机视口代替 Safari。

### 13.3 存储与恢复门槛

真实 MinIO 和生产实际启用 provider 通过匿名拒绝、短时签名、正确 MIME/inline、Range 206/416、失效后新请求失败、反代 Host/查询串保真。检查日志中不记录完整签名；验证改变分类或撤销批准后不能再签发。

完成一次新备份恢复到隔离环境并播放，同时验证旧备份和旧付费附件恢复。备份、GC、审批联动、目标浏览器四项任一未通过，不判定视频可上线。

所有后端测试仅连接各自可丢弃 TEST_DATABASE_URL，禁止生产库或两条 worktree 共用清表测试库。提交时运行受影响测试、类型/构建及契约检查，按仓库门禁等待最终 CI；本轮文档工作不声称已通过这些业务测试。

## 14. 回滚与后续扩展

### 14.1 回滚

先关闭新上传或新签发，前端恢复图片；保留视频资产、绑定、数据库字段和备份，暂不做破坏性迁移回滚。已有短时链接直到失效或传输结束仍有边界，不能宣称开关能即时撤回已下载内容。

不能回退到仍会扫描删除视频的旧 GC 版本；若必须回退整套服务，先停相关清理定时任务，保留 P1/P1.5 门禁和数据。更不能为恢复视频展示而绕过人工批准。

若暂停签发仍无法控制紧急传播，按实际存储能力处理指定对象或入口，并保留审计；这属于事件处置，不将删除全桶或更换所有供应商密钥列为常规回滚。

### 14.2 后续触发条件

不支持格式导致大量商家上传失败时，再评估自动转码和持久任务；播放卡顿与带宽成本有实测证据时，再评估 720p 备选、HLS/CDN；上传过长且确有中断痛点时，再评估直传和断点续传。

若人工公开视频审核达到既有 P1.5 运营触发线，再独立评估视频检测服务、音频转写与人工复核，仍需验证漏放和供应商数据条件。不把本文顺手扩成 AI 平台、通用媒体资产系统或付费课程交付系统。
