# Spec：AI 辅助新建商品

文档 ID：SPEC-AI-PRODUCT-002；版本：1.2.0；日期：2026-10-07。

## 目标与流程

管理员和已审核商家可以在新建商品入口选择「AI 帮我建商品」：描述商品 → 看预览并补充 → 确认草稿，经现有创建接口保存并进入编辑页。创建一个主规格，其他规格、图片、交付内容、库存和发布可在草稿中继续配置。人工新建入口保持可用，切换不覆盖原人工表单。

### 辅助工作台（1.1）

- 首次输入提供可选示例，仅在输入为空时可用，点击只填入公开合成介绍，不自动调用模型。
- 提取后同步展示商品预览和分组编辑。基本信息、交易设置、详细说明分组展开，优先展示需要补充的组；未知价格/交付/有效期明确显示待确认，不能展示成 0 积分或永久。
- 根据当前编辑值与模板实时列出待补充项，区分保存草稿必需项与发布前还需完善的参数。点击待补充项定位到对应编辑组。这个清单不是发布检查结果。
- 补充或修改公开介绍可再次整理。复用原有严格 description 请求，不发送已编辑表单、价格或交付内容；模型协议、提示和后端边界不变。
- 第二次及后续结果先暂存为候选，展示字段前后差异，默认全部不选。用户逐项采纳后才更新当前草稿，未选字段、人工售价及有效期保持。参数按字段比较；切换形态时，形态及所属商品/规格参数整体采纳，避免跨模板参数混用；交付不再兼容时清空并要求重选。人工 FAQ 不在模型输出能力内，始终保留。
- 可放弃候选并恢复上一版公开介绍。待比较或介绍已改未处理时不可进入确认/保存；失败保留当前编辑值，可重试或放弃本次介绍修改。无变化也必须明确结束本次比较。
- 最后一步展示当前商品内容、交易设置和后续工作；必须人工确认后才创建草稿。返回编辑保留内容，并取消之前的确认。字段变化同样取消确认。请求取消、重复提交和过期响应保护保持。

AI 提取结构化参数，并在原文支持的范围内扩写商品文案，不负责填补事实。形态和分类是候选建议；全部结果在保存前须由用户明确核对。价格、有效期和交付方式由用户填写/选择；不从模型输出采纳。未知有效期不默认为永久，用户必须明确选择天数或无固定有效期。草稿初始可售量为限量且为 0、仅登录可浏览；不设置自动开通，不生成库存、购买资料或付费交付内容。

## 配置、权限与运行时

这是商品 Copilot 的新建操作，与说明整理共用 `product_content_copilot` 开关及按角色每日配额，后台明确说明共用额度；服务地址、模型、密钥复用统一配置。不同操作使用独立 prompt/schema/validator。

- `GET /api/{admin|merchant}/products/draft-assistant` 返回 `{available:boolean}`，不暴露服务商或密钥。
- `POST /api/{admin|merchant}/products/draft-suggestions`，严格请求 `{description:string}`，1..4000 字符。禁止传入产品 ID、身份、密钥、付费内容和其他编辑器 DTO 字段。
- 继承各自新建接口的 active user / admin + MFA / approved merchant 权限链。没有既有商品读取，不存在跨商品或跨租户查询。
- 仅 `runAiGeneration` 调用 provider，`targetType=product_draft`，`targetId=actorUserId`，用于该用户新建操作的并发去重；不创建占位商品。迁移只扩展 `AiGeneration_targetType_check`。
- 元数据不保存输入、输出或问题原文；生成本身不写 Product/Offer。失败计入调用额度，参数/权限/上下文超限失败不计入。
- 固定 `product-draft@2`、`product-draft-validator@2`、reasoning=none、maxOutputTokens=6000。前端超时 55 秒，现有运行时超时与错误码保持一致。

## Projection

`draftAssistant/projection.ts` 显式构造并标记 AiSafe：

- `facts.templates[]`：本地模板 key/label，productFields/offerFields[] 的 key/label/type、枚举 value/label；不复制 schema 或模板对象。
- `facts.categories[]`：当前可用分类的 id/label。
- `facts.product=null`：商品尚未创建，没有已核实商品事实。
- `declared={}`；`untrusted.description` 为专用公开介绍输入，不读取其他表单内容或数据库商品。
- `truncated`：输入截断为 4000 字符；总 context 上限 24000 字符。仅可继续截断介绍；不可截断治理目录。仍超限则 422 AI_CONTEXT_TOO_LARGE，无模型调用、无配额扣除。

UI 提醒只输入可公开的介绍，不填账号、密码、卡密或实际交付内容；原文仅保留组件内存，不进浏览器持久存储。

## 输出与校验

静态 strict JSON Schema，全部字段 required，未知用 null/空数组。参数仍为 templateKey、categoryId、name、offerName、productAttributes/offerAttributes。文案分为短 description、introduction 分段数组、details.highlights；这些可扩写单元必须带 text 与 sourceQuotes（1–6 个原文片段）。详情段落标题由枚举 overview/content/audience/scope 映射成本地固定标题，每类至多一段，最多 4 段，每段至多 600 字。没有价格、库存、交付配置、URL、HTML 或身份类字段。

1. Ajv 完整 schema 验证类型、长度和数量；额外字段/不合法结构导致 AI_OUTPUT_INVALID。
2. 形态、分类只能引用本轮目录；名称、规格名和全部参数仍要求原文摘录，保留既有枚举、整数边界、重复键、模板字段验证。使用说明、购买须知和售后政策仍只摘录，不推断交易流程或政策。
3. 短简介、亮点和详细介绍允许重组、解释、润色。需有可用模板与原文商品名称；每个单元提供的全部 sourceQuotes 必须是输入中的原文片段。允许阐述原文含义与定性用途，不允许添加服务项目、资质、成果保证、交付承诺，不能把“未提供”改写成“不提供”，不输出“原文未说明”等编辑备注。短简介建议 60–140 字，详细介绍建议 3–4 个自然段、合计约 180–400 字；事实稀少时更短，不设强制最低字数、不填充重复套话。
4. 所有文本继续拒绝 H2/H4/H7（永久无限、保证退款、价格折扣等）和 HTML/链接/联系方式。可扩写单元内出现 H1/H3/H5/H6、数字、份/轮/页等数量、文件格式、服务/商业承诺关键词时，其所在完整句子必须与输入中的完整句子一致，且在该单元引用中出现；不能用同一个数字、词语或宽引用为不同含义背书。每一处分别校验；引用无效、H2/H4/H7 或禁用标记导致整单元丢弃，其他受保护事实未通过时只丢弃其完整句子，保留同单元中独立通过的完整句子，如果候选恰好是引用中唯一完整原句的连续片段，或仅重新排列了完全相同的逗号分句，可恢复完整原句，保留被省略的限定/否定；多义匹配或完整原句含禁用内容仍拒绝。不拼接半句、不编造替代文案。
5. sourceQuotes 只用于原文追溯和上述局部检查，不是语义证明，也不把自由文本升级为 facts。确定性检测无法枚举所有暗含承诺或识别所有归属错误；扩写结果始终是人工审核的文案候选。这是相对纯摘录模式更宽的表达边界，须通过 L3 的质量与对抗样本检查。
6. 短简介不可用时，只可原样复用本次已通过检查的 overview 段落，仍无内容则留空，不生成模板填充。响应将通过检查的段落拼成 introduction 纯文本，不返回引用原文/模型内部结构。前端明示“短简介 / 详细商品介绍”，可手动编辑、逐项比较并采纳。预览仅文本渲染，禁止解释模型 HTML。人确认创建时对 introduction 转义，再用固定 p/br 标签生成 richDescription，经过既有富文本存储净化，进入编辑页及商城介绍区；不新增存储字段或自动发布路径。

缺失信息或不相关输入返回空候选，用户可补充介绍重试或切回手动；不靠模型输出问题文案或伪造默认值掩盖缺失。生成途中不自动写表单，旧请求、关闭后的响应不可覆盖当前结果。再次生成展示逐项差异，人工表单独立保留。

## 验证

- Projection：复用 aiProjection 帮助函数，哨兵/键白名单/未知保持/截断/目录超限。
- Validator：无依据文本、编造整数、非法模板/分类/属性、额外敏感字段、重复字段、正常文本与枚举映射。
- 集成：管理员 MFA/商家权限、开关/配额、同用户新建去重、与说明整理共用额度、模型错误、元数据无内容、生成不创建商品，确认后仍由原接口创建 draft。
- 前端：只有显式点击才生成；可编辑预填、缺失交易字段阻止创建、确认前无写入、保存错误可重试、防重复提交、关闭后过期响应丢弃、原人工路径保持可用。
- L3：少量公开合成样本验证真实服务结构提取、原文校验、空输入语义和提示注入边界；不使用真实商品/客户数据。报告只在被忽略的 server/.ai-eval/ 下保存。

结构化输出并不保证事实正确，未知值必须有空值通道。依据：[OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)，2026-10-07 核对。
