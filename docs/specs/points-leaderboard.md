## 1. 当前产品规则

2026-10-05 用户确认两项调整：未设置头像的用户使用稳定的内置三国头像；排行榜使用自然周／自然月，包含今天并及时更新。此版本取代 1.0 的“截至昨日、每日快照读榜”和字母头像设计。

| ID | 规则 |
| --- | --- |
| LB-01 | 只累计窗口内 `PointLog.type = 'in' AND amount > 0`；out/hold/release/refund 不计。与会员等级累计获得口径一致，消费不降低累计得分。 |
| LB-02 | 业务时区 Asia/Shanghai。总榜全历史，本月榜从本月 1 日 00:00 开始，本周榜从周一 00:00 开始；不是滚动 30／7 天。 |
| LB-03 | 当前榜单窗口为 `[periodStartUtc, requestCutoff)`，总榜无左边界。包含今天已发生的流水；截止时刻及未来流水不计。 |
| LB-04 | 得分降序 → 窗口内最后一笔有效获得的时间升序 → userId 升序，名次唯一连续。同分先达到者靠前。 |
| LB-05 | 当前查询只纳入非 admin、非“已封禁”用户，merchant 参与。封禁资格变化不再等待每日快照刷新。 |
| LB-06 | 本期没有正额获得流水就不入榜，me 为 null。空榜代表本期无人得分，不等价于“新周期刚开始”或“系统生成中”。 |
| LB-07 | 他人只公开 rank / displayName / avatarUrl / points / isMe / prevRank，不下发他人 userId、原始 email 或余额。展示名为已保存昵称，空值回退稳定的三国风趣味昵称。 |
| LB-08 | Top 100、个人名次、名次变化基线和公开身份在一条 SQL、同一 MVCC 视图内读取，最多返回 101 行到应用层。 |
| LB-09 | 打开页面、切榜、手动刷新立即查询；可见页面每 60 秒重拉，回到标签页时刷新；同一页面请求不重叠，过时 scope 响应不覆盖当前榜。 |
| LB-10 | `prevRank` 是同一自然周期内截至今日北京时间 00:00 的排名。反复查询不改变基线；新周期首日和今日首次得分用户为 null，显示“新”。 |
| LB-11 | 时间边界使用 businessTime helpers。PG 存储是无时区的裸 UTC，绑定参数通过 `timestamptz AT TIME ZONE 'UTC'` 转成相同语义；不依赖主机或数据库会话时区。 |

## 2. 头像

固定 v2.3 的 24 人名单按不可变用户 ID 分配默认头像，不按昵称、邮箱或每次随机数分配。个人资料、头像选择预览、桌面导航、移动导航与排行榜使用同一映射。用户已保存的预设或上传头像优先；清除后恢复同一默认头像。

默认头像在展示时计算，不批量改写 User.avatarUrl；不新增字段或迁移。排行榜由服务端投影最终 avatarUrl，无需向浏览器暴露他人 ID。内置资源继续使用 48/96/443 响应式尺寸和原版本路径。图片实际加载失败时才回退首字符。

## 3. API 与页面

`GET /api/leaderboard?scope=total|month|week`，缺省 total。仍要求 authenticate + requireActiveUser，匿名 401、封禁 403、非法 scope 400。

```json
{
  "scope": "week",
  "periodKey": "W2026-10-05",
  "periodLabel": "2026-10-05 ~ 2026-10-11",
  "dataThrough": "2026-10-05",
  "updatedAt": "2026-10-05T04:00:00.000Z",
  "top": [{ "rank": 1, "displayName": "星河", "avatarUrl": "/assets/avatars/three-kingdoms/v2.3/wei-cao-cao.webp", "points": 100, "isMe": true, "prevRank": null }],
  "me": { "rank": 1, "points": 100, "prevRank": null }
}
```

- `dataThrough` 是统计截止时刻所属北京日期；`updatedAt` 是查询过滤流水所用的准确时刻，空榜也返回，不再借用总榜快照的时间。
- 周区间展示完整年份，避免跨年周含义不清。
- 页面明确显示北京时间截止时刻、自然周期起点、每分钟更新、名次变化对比今日零点。
- 后台重拉失败保留原数据及原截止时刻，提示更新失败；初次加载失败提供重试，切换 scope 失败不展示其他 scope 的数据。
- 颁奖台保留 2-1-3 布局及金银铜头像框，榜单不足三人保留虚位；第 4 名起为列表。Top 100 外仍返回精确 me。
- 不满 100 人时将末位称为“当前末位”，达到 100 人才称“上榜线”；与入榜线同分明确显示同分。

## 4. 历史快照与读侧负载

`LeaderboardEntry` 和原每日 cron 保留用于历史归档，当前接口和名次变化不依赖它们。历史写侧仍按截至昨日的窗口聚合、事务替换，并持续补刷最近已结束的周／月；此语义与当前查询分开，不将旧快照伪装成新数据。

当前查询从 PointLog 做数据库内聚合和窗口排名，复用 `(type, createdAt)` 索引及资格谓词；不在每次 GET 重写整张快照表，不把全榜加载到 Node。前端只在可见时每分钟查询，没有引入 Redis 或新依赖。总榜仍需聚合历史有效流水；数据量增长时应以实际查询计划评估增量聚合，不能仅靠提高轮询频率扩容。

## 5. 验证要求

- 后端：既有快照／鉴权／隐私测试；当前榜单测试覆盖当天入榜、周一与月初、跨年周、毫秒边界、未来流水、UTC/Shanghai/New_York 会话、Top 100 外个人排名、同分排序、资格变化和稳定头像。
- 前端：头像随改名稳定、自选／上传／清除、排行榜图片投影、北京时间显示、60 秒重拉、隐藏页暂停、切榜乱序响应、刷新失败保留截止时刻。
- 浏览器：复用排行榜与个人头像冒烟，验证真实头像资源加载、页面布局、选择后刷新持久化；纯空态断言下沉组件测试。
- 前后端生产构建；无数据库迁移、真实用户批量写入或部署操作。
