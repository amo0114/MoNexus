# 商品模型与结算链路改造总纲（Spec）

> 状态：已确认方向，分阶段实施。本文档是各阶段的唯一真相来源；阶段任务清单见 `.claude/plan/phaseN-*.md`。
> 创建：2026-07-25

## 1. 背景与问题

当前模型只能覆盖"简单数字商品"：

- `Product.type`（网络节点/共享账号/充值卡密/邀请码）只是展示分类，不改变数据结构或下单流程。
- 三种履约方式的交付内容最终都是一段纯文本（`InventoryItem.content` / `Product.fixedContent`），无法表达账号/密码/到期日等结构化信息，也无法做受控文件、购买前信息收集、预约/里程碑等能力。
- 支付链路缺口：确认弹窗不显示余额前后对比、不区分"冻结"与"扣除"；前端价格来自较早加载的数据，商家改价时用户无机会针对最终价格重新确认；**后端没有幂等键**，网络重试/多标签页可产生两笔有效订单。

## 2. 目标形态：四层模型

1. **Product（商品）** — 公开展示：名称、图文介绍、分类、封面、商家。类别降级为纯分类标签。
2. **Offer / SKU（规格套餐）** — 一个商品多个套餐（月卡/季卡、地区、容量），各自独立价格、库存、履约策略。
3. **Fulfillment（交付策略）** — 绑定到 SKU 而非商品。保留现有三种模式并兼容历史数据，逐步扩展：结构化库存（账号包）、受控数字内容（MinIO 短期签名下载）、订阅/开通型服务。
4. **交付物（结构化内容）** — 字段化展示（account/password/region/expiresAt…）。敏感字段只允许订单所属买家、商家、必要管理员读取；**绝不进入商品公开接口、列表接口或审计日志**。

商品创建从大弹窗升级为独立分步创建页：选模板 → 展示信息 → 套餐价格 → 交付方式专属配置 → 购买前表单 → 预览发布。**模板只负责引导和默认字段，不锁死业务。**

## 3. 结算链路目标

- 所有订单经过"结算确认"：服务端提供报价与余额前后值（`当前可用余额 → 支付后可用余额`）；人工服务明确显示"冻结积分，履约后扣除，拒单/退款返还"。
- 售罄或改价时提示"商品信息已变化，请重新确认"，**禁止静默按新价格成交**。
- 确认接口必须幂等：同一结算意图（双击/超时重试/网络重放）只对应一笔订单和一次积分扣减。
- 高风险订单二次验证（可配置）：高额、当日累计超阈值、新设备/长登录态触发；首版用登录密码再确认，长期演进 WebAuthn/Passkey。**不引入独立支付密码**（需要额外的设置/重置/锁定/风控体系，首版不值）。

## 4. 已确认的取舍决定

| 决定 | 理由 |
|---|---|
| 首版**不做** `POST /checkout/prepare` + `confirm` 两段式 | 需引入 Checkout 实体、TTL、过期清理。等价轻量方案：下单接口附带 `expectedPrice` + `Idempotency-Key`，价格不符返回 409；余额预览由只读 `GET /checkout/preview` 提供。SKU 与购买前表单落地后再升级为正式两段式 |
| 幂等键独立先行，不依赖商品模型改造 | 纯后端小改动，立即消除现存的重复扣款风险 |
| 第一阶段不碰 SKU | SKU 迁移影响面大：`InventoryItem`/`InventoryLog`/`Order`/`Settlement`/`Review` 全部挂在 `productId`，含唯一约束 `@@unique([productId, content])` 和商家库存导入流程 |
| 不堆叠硬编码类别 | 类别不再驱动数据结构；模板机制承担引导职责 |
| 二次验证首版 = 登录密码 | 无独立支付密码体系；低额订单不触发，避免体验割裂 |

## 5. 不变量（所有阶段必须保留）

以下现有设计已验证正确（`server/src/modules/orders/service.ts`、`server/prisma/schema.prisma`），任何阶段不得破坏：

1. **单事务下单**：扣积分 + 锁库存 + 订单 + 交付 + 结算在一个 DB 事务内。
2. **库存并发安全**：`FOR UPDATE SKIP LOCKED` 领取库存项；`stock > 0` 条件更新防超卖。
3. **积分原子性**：instant 模式 `debitAvailablePoints`；manual_service 模式 `holdAvailablePoints` 冻结（`holdingPoints` + `frozenBalance`）。
4. **订单快照**：`deliveryModeSnapshot` + 商品展示快照字段。未来扩展 SKU/交付配置/购买前表单时，**同样要在下单时快照进订单**，商家改商品不得影响已购用户。
5. **敏感内容访问控制**：交付内容（含未来的购买前表单数据、结构化交付字段）沿用 `DeliveryRecord.content` 的访问边界——仅买家/商家/必要管理员，禁止公开序列化、列表接口、审计日志。
6. **整数积分运算**：不引入浮点金额。
