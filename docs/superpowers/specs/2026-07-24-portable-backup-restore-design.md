# 可移植备份与恢复（Portable Backup & Restore）设计

## 目标

让管理员能够从旧 MoNexus 实例的管理后台创建一个完整、加密、可下载的备份包，
在另一台已部署 MoNexus 的新实例中通过管理后台上传并恢复业务数据与对象文件。

该能力是**应用级迁移**，不读取 Docker volume、不挂载 Docker socket、不依赖
1Panel、Caddy、OpenResty 或任何特定云厂商；数据库使用 PostgreSQL、文件使用
S3 兼容对象存储即可运行。

## 用户路径

```text
旧实例的管理员
  -> 管理后台 / 数据备份与恢复
  -> 输入备份口令，创建并下载 *.monexus-backup

新实例的引导管理员
  -> （没有任何用户时）/restore-setup 输入新实例的恢复引导令牌并创建引导管理员
  -> 登录后进入管理后台 / 数据备份与恢复
  -> 上传 *.monexus-backup，输入同一口令并确认恢复
  -> 对象先恢复，数据库后恢复，保留当前引导管理员
```

恢复完成后，管理员使用新实例的引导管理员继续登录；导入的所有用户、商品、订单、
积分、商家、公告、评价、库存和上传对象会保留。运行环境的 `.env`、JWT 密钥、
数据库密码、对象存储密钥、SMTP/Sentry 配置永不写入备份包。
如新实例的图片 CDN、域名或 bucket URL 不同，项目会按对象 key 自动将商品图地址改写为
新实例存储配置生成的地址；非 MoNexus 的外链图片地址保持原样。

## 备份包格式（v1）

文件扩展名为 `.monexus-backup`，由以下三部分组成：

1. 固定 magic 与 JSON header：格式版本、scrypt 参数、salt、IV 与加密算法；
2. AES-256-GCM 密文：压缩 tar 内容；
3. 16 字节 GCM auth tag。

解密 tar 包包含：

```text
manifest.json        # 格式版本、创建时间、应用版本、校验和、对象清单
database.dump        # pg_dump --format=custom --no-owner --no-privileges
objects/<digest>     # 每个 S3 对象的内容；原始 key 只记录在 manifest
```

对象使用摘要作为 tar 内文件名，避免任何对象 key 造成路径穿越。`manifest.json`
记录原始 key、大小与 SHA-256；恢复前先校验包结构、认证标签、转储及每个对象的
摘要。

## 服务端边界

- Server 镜像增加 PostgreSQL 16 client，使用 `pg_dump` / `pg_restore` 与 PostgreSQL
  协议通信；不调用 Docker CLI。
- 存储适配器扩展为列举、流式读取、写入对象，支持现有 MinIO、R2、S3 等实现。只迁移
  MoNexus 内容寻址图片 key（`<32 位 sha256 前缀>.<图片扩展名>`），不会把共享 bucket 中
  的无关对象打进包内。
- 打包、加密、解密只使用应用容器的临时工作目录；任务完成或失败后清理。
- 管理端只允许一个备份或恢复任务同时运行；口令只在请求生命周期内使用，绝不写入
  数据库、日志、审计详情或任务状态。
- 备份文件通过认证下载接口提供；恢复文件通过认证上传接口接收。首版是完整备份，
  不做增量、合并或跨实例同步。

## 导入安全规则

1. 仅当前、有效的管理员可以创建、下载、上传、导入；全部动作写 `AdminLog`。
2. 口令至少 12 字符；错误口令、损坏包、未知格式与版本不兼容均 fail-closed。
3. 导入仅允许“空实例”：除当前登录的引导管理员外，不得存在用户、订单、商品、
   商家、库存、积分流水或结算等业务数据；目标对象存储不得有与备份中同名的
   MoNexus 文件。无关的共享 bucket 对象不会被读取、覆盖或删除。
4. 当前引导管理员会在数据库导入后被重新写入为正常的 admin，确保操作者不会失去
   新实例控制权；这也是目标实例唯一不来自备份的记录。
5. 所有导入的 RefreshToken、密码重置 token、邮箱验证 token 被撤销/删除，避免把
   旧站会话带到新站。
6. 先上传并校验对象，再以 PostgreSQL 单事务恢复数据库。对象恢复失败时，目标数据库
   仍保持空状态；`pg_restore` 本身失败时事务回滚、系统会尝试删除本次已写对象。
   数据库已经提交后发生兼容迁移或后处理错误时，目标实例必须重建/清空后重试，不能在
   不明状态下合并导入。
7. 新实例必须预先配置自己的环境变量和对象存储；导入不触碰这些配置。
8. 新实例尚无管理员时，运营者可在其 `.env` 设置一个全新、高熵的
   `PORTABLE_RESTORE_BOOTSTRAP_TOKEN`，再通过 `/restore-setup` 创建唯一的引导管理员。
   该入口只在 `User` 表为空时可用，令牌使用常量时间比较；导入后应清空该环境变量并
   重启服务。

## 管理接口

```text
POST /api/admin/portable-backups/export
GET  /api/admin/portable-backups/:id
GET  /api/admin/portable-backups/:id/download
POST /api/admin/portable-backups/import
```

前端页面展示任务进度、校验错误、下载入口、导入前风险确认，以及“仅空实例可导入”
的状态。上传接口的大小上限由 `PORTABLE_BACKUP_MAX_BYTES` 控制；反向代理需要允许
至少同等大小的请求体，但功能本身不依赖某个代理产品。仓库内置 Nginx 只对精确的
`POST /api/admin/portable-backups/import` 放宽至 2 GiB，普通 API 继续保持 10 MiB；
其他反向代理应复刻此精确路径规则，而不是全站放开上传上限。

## 验收与回归

- 非管理员、封禁管理员、错误口令、损坏/篡改文件、超限上传均被拒绝；
- 导出包不含环境变量、机密或对象存储凭据；
- 数据库转储、对象清单、SHA-256 与 GCM 认证均验证；
- 非空目标实例拒绝导入；
- 空目标从导出包恢复用户、订单、积分、库存、商品图与公告；
- 引导管理员保留，旧 refresh/reset/verify token 不保留；
- 前后端构建、管理员 API 回归和至少一条“导出 -> 空目标导入”的集成测试通过。

## 非目标

- 不替代云硬盘快照或异机灾备；
- 不导入 `.env` 或宿主机/反向代理配置；
- 不支持向已有业务数据的实例合并导入；
- 首版不支持计划任务、自动上传、增量包或一键覆盖生产实例。
